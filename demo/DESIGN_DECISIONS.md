# 試玩版：設計決定、缺口與限制

> 這份是「我替你定了什麼」「還沒定什麼」「這個設計誠實的極限在哪」。給你看，也給代理看。

## A. 這一輪補上的缺口（之前沒想完）

| # | 缺口 | 怎麼補 |
|---|---|---|
| 1 | 資料檔的觸發條件是寫給人看的文字，引擎無法直接執行 | `flow.yaml`：50 條事件→動作規則、9 個引導階梯、運算式文法、對話執行期規則 |
| 2 | 沒有「標準答案」可以驗證引擎寫對沒有 | `tools/flow_sim.py`（Python 參考模擬器）＋ `testvectors/walkthrough.json`（4 條走法、逐 commit 的預期結果） |
| 3 | 存檔「驗證」被說得太滿（雜湊鏈任何人都能重算） | `integrity.yaml`：安全規則（硬拒絕）與可信度（只標記）分開；文案只准說「完整／可疑／損毀」 |
| 4 | 匯入代碼沒有安全規則 | 長度、解壓上限（256 KiB）、commit 數、欄位白名單、暱稱格式、整數限定、巢狀深度；30 個必拒測資 |
| 5 | Python 與 JS 兩邊實作可能互不相容 | `testvectors/vectors.json`：規範化、commit id、CRC32、可接受／可疑／必拒 |
| 6 | 前端的模擬 shell 沒有對照答案 | `testvectors/conformance.json`：真 bash 在試玩版檔案系統上跑的 71 個案例＋7 個快題判定 |
| 7 | 資料 bug：遺物 R0 要求 `ln <檔> ~/keep/`，但 `~/keep` 不存在 | 引擎寬鬆處理（目的以 `/` 結尾且不存在就建立）；不新增資料夾（避免洩漏提示） |
| 8 | 資料 bug：`B0.yaml` 的 `requires: flag.b0.read_lost0` 沒人設定 | `flow.yaml` 的 `r.read_lost0` |
| 9 | 卡住的狀態沒有下一步（例如點完燈不開分支、做完 Ch0 不渡海、投票沒反應） | 9 個引導階梯 + 31 個新的 INIT 節點 |
| 10 | YAML 1.1 把 `on:` 解析成布林 `true`（PyYAML 等），規則會悄悄失效 | 事件欄位改名為 `event`，並寫進 `yaml_gotcha` |

## B. 我替你定的預設值（沒有人叫我決定的）

| 編號 | 決定 | 理由 |
|---|---|---|
| D1 | **技術**：一個自給自足的 HTML 檔（`dist/index.html`），原生 JavaScript（ES2020），建置時可用 esbuild 打包、js-yaml 把資料編譯成 JSON；執行時不載入任何外部資源；解壓用內建於專案的 pako。測試用 Node 18+ 的 `node --test` | 攤位筆電可能沒網路；`file://` 打開也要能跑（ES module 在 `file://` 會被擋，所以要打包成單檔） |
| D2 | 快題**依序啟用**，但最近 20 筆指令歷史會**補登** | 新手搶先打對不會被浪費；也讓 `task` commit 的順序穩定，可信度檢查才有意義 |
| D3 | 旗標**不分分支**，全域共用；分支只共用 `branch` 標籤 | 簡單；B0 的目標是教「分支裡弄壞東西不要緊」，不是教旗標隔離 |
| D4 | `skip` 要輸入兩次（10 秒內） | 防止誤觸；不扣分，只是不算那題的 10 分 |
| D5 | `rm -rf ~` 在分支裡會清空內容但保留家目錄；在 main 上被攔下 | 讓 cwd 永遠有效；B0 的教學重點是「在 main 上被擋、在分支裡可以」 |
| D6 | 口令階段答錯會留在輸入模式；但輸入看起來像指令（例如 `cat handbook.md`）就自動離開、當指令執行 | 新手最容易卡在這裡：口令在手冊裡，要先去讀 |
| D7 | `hint` 與 30/60/90 秒閒置共用同一個階梯計數；最後一階給完整答案並標記 `used_full_hint` | 一個機制，兩個入口，行為好預測 |
| D8 | 15:00 時若玩家正在投票，多給 60 秒；仍沒投就以「未投票」結束 | 不在玩家按鍵途中切走畫面；但活動的 15 分鐘不會無限延長 |
| D9 | 值班證在畫面上用 DOM 卡片顯示（不是等寬字元排版）；「複製成文字」才輸出純文字版 | 中日韓字元在不同字型下寬度不一致，等寬排版會歪 |
| D10 | 只有繁體中文（zh-TW）；字型用系統字型堆疊，不載入網路字型 | 離線 |
| D11 | 存檔自動存在 `localStorage` 的 `ra.demo.save.v1`（全部包 try/catch） | 私密視窗與清除網站資料都會讓它消失，所以結尾一定顯示代碼 |
| D12 | 排行榜只收「完整」的存檔，且標註「自行回報，僅供參考」；活動現場想要可信的名次，只收 kiosk 或主持人看著玩的 | 見下方 C |
| D13 | QR 是選配（用離線函式庫在前端產生）；代碼太長（> 1,200 字元）時才分成兩個 | 預期一個就夠 |
| D14 | 不放音效、不放音樂 | 活動現場很吵；也少一個要驗收的東西 |

## C. 誠實的極限

1. **前端存檔無法防作弊。** 雜湊鏈只能抓「不小心改壞」。任何會寫程式的人都能產生一份「看起來完整」的存檔，並且給自己一個最高分。可信度檢查（太快、順序不對、投票早於 02:00 的名字）只能擋最粗糙的偽造。真正防作弊需要伺服器重放事件或簽章，那是正式版線上模式的事。
   → 活動實務：排行榜當成「參加紀錄＋氣氛」，獎品給「現場看著玩的人」或抽籤，不要給「分數最高者」。
2. **發現（finds）的偵測在前端。** 前端判斷你有沒有 `cat shelf/jar.txt`，存檔庫無法再驗證。
3. **時間（`r`）是前端的虛擬時鐘寫進去的。** 它只用於活動統計，不能當證據。
4. **試玩版的日誌只有 3,315 行**，所以 Q1-1、Q1-3 的答案與正式版（約 120 萬行）不同；匯入時這兩題不帶過去。這是刻意的。
5. **模擬器不是真的 Linux。** 白名單 29 個指令；管線與重導向只支援最常見的組合；不支援的 bash 語法（`$(...)`、迴圈、函式、heredoc、萬用字元以外的展開）可以回 `bash: 不支援的語法`，但不能當掉。
6. **還沒有任何真人試玩過。** 時間預算（15 分鐘）來自我的估計與假玩家，不是量測。第一次真人試玩要記錄實際時間與卡關點（見 `DEMO_AGENT_CHECKLIST.md` A 節）。

## D. 還沒設計、需要你決定的事

| 問題 | 為什麼需要你 | 我的預設 |
|---|---|---|
| 活動是哪一種（攤位／自助／講座暖場）、多久、多少人 | 決定要不要 kiosk 與 host-led | 先做三種都支援，驗收只要求 kiosk 與自助 |
| 要不要收 email 通知名單 | 有隱私與法規面 | 不收；EVENT_KIT 只寫了「若要收，必須是分開的、可不填的欄位」 |
| 視覺風格（美術、字型、配色、有沒有 logo） | 我沒有美術資產，也沒有品牌決定 | 純文字終端機風格，深色＋高對比兩種主題，沒有圖片 |
| 試玩版的網址與託管 | 任何靜態空間都行（GitHub Pages、自己的 VPS） | 單檔，不依賴伺服器 |
| 正式版的存檔格式是否沿用 schema 1 | 影響匯入承諾 | 沿用；`integrity.yaml` 的形狀規則隨正式版擴充 |
| 排行榜是否公開（現場投影？） | 暱稱可能被惡搞 | 只顯示暱稱與分數；暱稱格式限制為英數 12 字，沒有自由文字 |

## E. 風險登記

| 風險 | 嚴重度 | 緩解 |
|---|---|---|
| 15 分鐘實際上變 20 分鐘 | 中 | 硬上限＋14:00 預告＋`skip`；真人試玩後調整 est |
| 新手在口令（`lamp-before-sudo`）卡住 | 中 | 三階提示＋輸入指令自動離開輸入模式 |
| JS 與 Python 的 zlib／JSON 邊角行為不同 | 中 | 對照測資只比結論不比位元組；浮點數一律拒絕；字串限制為 ASCII |
| 前端自己的 bug 讓存檔無法匯入 | 高 | 匯出前自我檢查（匯出→匯入→比對鏈尾），失敗就警告並提供原始 JSON |
| 有人貼惡意代碼 | 中 | 硬規則 + 30 個必拒測資 + 暱稱只用 `textContent` 顯示 |
| 活動現場筆電當機 | 低 | 本機自動存檔；備用筆電；代碼拍照 |
