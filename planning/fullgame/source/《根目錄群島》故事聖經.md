## 1. 時間線分支系統

歷史唯讀，探索在分支：`main` 永遠不會被改寫，分支裡可以改變一切，但只有「知識」能回到主線。這一條規則同時是世界觀、玩法和存檔格式。

### 核心規則

1. `main` 是正史（canon）。只有主線進度與季末投票能在上面追加 commit，不能改寫，也不能刪除。
2. 每章結尾、每次重大選擇之前，系統自動打一個檢查點，名稱形如 `ckpt/ch2-gate`。
3. 在任何檢查點都能 `git checkout -b <分支名>`，進入那一刻的世界副本。
4. 分支內可以改任何東西：做不同決定、拿不同物品、走向不同結局。這些全都碰不到 `main`。
5. 離開分支只有三條路：`merge --knowledge`、`abandon`、`tag`。
6. 跨分支流通的貨幣只有一種：**知識卡**。主線裡有些門只認知識卡，不認物品，也不認等級。

歷史沒有被改寫，但你知道的事改變了你在歷史裡能做的事。這就是「追尋真相」在這個世界裡唯一合法的管道。

### 三種分支類型

| 類型 | 指令 | 能不能寫入 | 玩法 | 例子 |
| --- | --- | --- | --- | --- |
| 回溯分支（flashback） | `git checkout <舊 commit>` | 唯讀。你是觀測者，NPC 看不見你，只能讀、搜尋、跟隨 | 調查過去：讀當時的檔案，重播當時的終端畫面 | lin 最後一夜的郵局 |
| 假設分支（what-if） | `git checkout -b whatif/<名>` | 可寫入的模擬，世界回報「模擬結果」 | 改掉過去的某個決定，看後果；結果以知識卡帶回 | 如果當時封鎖了 GC 的探測 |
| 平行分支（parallel） | `git checkout -b alt/<名>` | 完整可玩，直到那條支線的結局 | 走另一條劇情路線；結局可封存收藏 | 另一種結案方式 |

### 離開分支的三條路

| 指令 | 效果 | 帶回主線什麼 | INIT 的反應（範例） |
| --- | --- | --- | --- |
| `merge --knowledge` | 只合併知識 | 線索、真相、NPC 的記憶、解鎖的對話選項。不帶回物品、領地、被改寫的事件 | `[init] 已合併 1 張知識卡。歷史未被更動。` |
| `abandon` | 丟棄分支 | 只留下一句「殘影」短語，寫進 reflog | `[init] 分支已捨棄。懸空 commit 3 個，等待回收。` |
| `tag` | 封存為平行結局 | 收藏、成就；不影響主線 | `[init] 已標記 alt/another-ending。它不會再被改動。` |

### Reflog 與 GC：被丟棄的分支會發生什麼事

被丟棄的分支不會立刻消失，它變成懸空 commit。在期限內可以用 `git reflog` 找回；期限一過，就被 GC 回收。這跟真實 git 的 reflog 與 `git gc` 是同一個概念，期限數字遊戲內自訂。

這讓 GC 在敘事裡多了一層意義：它回收的不只是島，還包括「沒有人再引用的可能性」。每天 02:00 的回收日誌會多一行：

```
[gc] sweep complete: 7 sectors, 3 dangling commits reclaimed
```

玩家會發現，有些走過又放棄的路線，在日誌裡留下了數字。

### git 指令即機制

| git 指令 | 遊戲機制 |
| --- | --- |
| `log --graph --all` | 世界歷史地圖：列出所有賽季、分支與署名 |
| `blame` | 追問每一行是誰寫的，例如憲章第七條出自誰手 |
| `bisect` | 二分搜尋，找出世界從哪一個 commit 開始壞掉（一種固定的謎題類型，對應 OJ 的二分搜尋題） |
| `cherry-pick` | 從隊友的分支只拿走一張知識卡，不帶走其他東西 |
| `stash` | 暫存進行到一半的謎題，離開再回來 |
| `diff` | 比對兩個時間點，也是解合併衝突的主要工具 |
| `reflog` | 找回被丟棄的分支 |
| `tag` | 封存結局與檢查點 |
| `revert`、`rebase`、`fork` | 季末投票的三個選項，加上一個隱藏選項 |

### 存檔即 repo

存檔不是一份狀態快照，而是一串 commit 紀錄（事件溯源）。世界狀態等於把 commit 依序重放的結果。分支只是指向某個 commit 的指標，所以開分支幾乎不花空間。

一個 commit 的內容：

```yaml
id: c0a17f
parent: b93e02
branch: main
actor: op-demo
chapter: ch2
action: {type: cmd, cmd: cat /etc/charter}
delta:
  flags: [charter_read]
  items: []
  knowledge: [K0-draft]
t: 1761560000
```

存檔資料夾的結構：

```
save/
├── HEAD                     目前所在分支
├── refs/heads/main
├── refs/heads/whatif/block-gc
├── refs/tags/ckpt/ch2-gate
├── objects/                 commit 與周期性快照（內容雜湊）
└── knowledge.json           已合併的知識卡
```

合併規則：知識卡取聯集並附可信度；物品、領地、被改寫的事件一律不合併。快照每隔固定數量的 commit 存一次，重放才不會太長。

### 合併衝突就是協作謎題

多人離線與連線時，隊員各自在分支裡探究，帶回來的知識可能互相矛盾，合併時出現衝突標記：

```
<<<<<<< ada/branch-mail
postmaster 說：信在 02:00 被退件
=======
sentry 說：那封信根本沒有寄出
>>>>>>> bo/branch-gate
```

團隊必須用 `git diff` 比對證據，例如日誌時間戳、郵件標頭、檔案修改時間，推理出哪一份為真。衝突分三種：

- 證詞衝突：兩個 NPC 說法不一致。
- 時間線衝突：兩人記錄的時間差十七分鐘。
- 物品衝突：兩人都拿了唯一一把鑰匙，但只有一份能被合併。

設計原則：**每個衝突都至少藏一個「兩者皆真」的解。** 例如郵件確實被退件，也確實沒有寄出，因為它被退件的時刻，寄件人已經被回收了。鼓勵玩家調查到底，而不是二選一。

選錯的後果：被選掉的知識卡標成 `disputed`，之後在某個事件裡反噬，例如守護夜班誤判一個正常行程。解開衝突的人會在合併 commit 上留下簽名，連線時進名人堂。

### 三種遊玩層級的分支差異

| 層級 | 存檔位置 | 分支數量與成本 | 同步方式 | 合併衝突 |
| --- | --- | --- | --- | --- |
| 單人離線 | 本機 `save/` 資料夾 | 同時最多 5 條，無成本 | 無 | 不會發生，合併時只需確認 |
| 多人離線 | 存檔可 push／pull：檔案、剪貼簿字串、區網 | 每人各開分支，共用 `main` 的副本 | 手動交換 | 會發生，是協作謎題 |
| 連線 | 世界伺服器 | 每次回溯消耗 1 單位「時間燃料」，每日補充 3，全隊共享 | 即時或輪詢，伺服器重放驗證 | 會發生，正史由全服在季末投票寫入 |

連線版收費是因為回溯等於免費情報；時間燃料讓開分支成為一個要想過再做的決定。

### 寫作約定

- 每章恰好有一個「主分支點」，但玩家可在任何檢查點自行開分支；自行開的分支只有 INIT 的通用模擬回應。
- 回溯分支必須揭露一個主線沒提過的事實。
- 假設分支的結果不得得出「歷史被改變」的結論，因為那只是模擬。
- 平行分支的結局可以封存，但不得提供主線缺少的必要知識。
- 在分支裡，INIT 的口吻會變：它會說「這是模擬」，並在每條訊息前面加上分支名稱。

## 2. 世界設定速覽

一句話：斷網之後，世界只剩浮在封包海上的伺服器島嶼；上一任管理員失蹤，root 被拆成八片藏在各島，而每天 02:00 都有一支叫 GC 的程序在回收「沒人需要」的東西。這一節讓整份文件不依賴其他資料就能讀懂。

### 世界物理（遊戲裡成立的規則）

- **延遲即距離。** 島與島之間用 `ssh` 渡海，延遲越高，渡海越久、風險越大。
- **電力與冷卻是資源。** 每座島有電力預算，算力吃緊時日誌會變慢。
- **被引用的東西不會被回收。** 這是 GC 唯一的法則，也是 lin 用來藏鑰匙的方法。
- **黑潮是 `/dev/null`。** 被回收的一切沉入黑潮，從此讀取只得到空字串。
- **賽季以閏日為終點。** 每個賽季的最後一天是世界曆的二月二十九日，GC 在那天做一次無法抵抗的大掃除。這是整個賽季的倒數時鐘。

### 世界年表（玩家要挖才拿得到）

| 版本 | Admin | 特質 | 事件 | 遺物（可在哪找到） |
| --- | --- | --- | --- | --- |
| v0.x | 無 | 無 | 大斷網。首批機房成為孤島 | `/var/log/boot.0`，只有三行 |
| v1.x | `moth` | 好奇的園丁 | 訂下島嶼命名規則；GC 原本只是一支好心的清理腳本 | 一只標本罐，裡頭夾著第一隻 bug 的 ASCII 圖（燈塔的書架） |
| v2.x | `kestrel` | 立法的鷹 | 立下值班制憲章；封包海爆發第一次島嶼戰 | `/etc/charter`，七條 |
| v3.x | `ferrous` | 囤積的鐵 | 獨佔十一座島；世界第一次 OOM，GC 被迫升級成強制回收 | 一本十一頁的帳冊，每頁一座島，最後一頁空白 |
| v4.x | `lin` | 安靜的守夜人 | 把 root 金鑰拆成八片，用硬連結藏在各島；在憲章第七條動過手（v4.7），另提第十條修憲案卻被 CI 擋下；失蹤 | 值班室的筆記與 `.bash_history` |
| v5.0 | 空缺 | 無 | 玩家加入，MOTD 版本號即賽季數 | 本季 |

世界時間不等於現實時間：一個賽季就是世界裡的一次 release。

### 角色群

| 角色 | 身分 | 說話風格 | 在故事裡的功能 |
| --- | --- | --- | --- |

### 四大陣營（House）

| --- | --- | --- | --- | --- |

### 八片鑰匙碎片

lin 把 root 拆成八片，每片用硬連結（`ln`）綁在島上的某個檔案，所以 GC 無法回收。碎片本身不會說話，它的藏匿方式就是各島的謎題。

| 碎片 | 所在 | 藏法 | 取得方式 |
| --- | --- | --- | --- |
| F1 | 燈塔 | `~/notes/.draft.txt` 內 | 用 `grep -r` 找出 `KEY-FRAG` |
| F2 | 日誌港 | `lost+found/#3141` | 用 `fsck` 復原殘缺檔案 |
| F3 | 權限堡 | `/etc/charter.d/.seal` | 解開權限與憲章的關卡 |
| F4 | 郵局島 | lin 未寄信件的附件 | 從 `/var/mail/spool` 找出那封信 |
| F5 | 排程礦坑（支線） | 閏日排程的註解 | 讀懂 `0 0 29 2 *` |
| F6 | 網路群礁 | 唯一仍可連通的一跳 | 解出繞開墳墓的航線 |
| F7 | 記憶體沼澤 | GC 本人保管 | 撐過回收波，GC 才交出 |
| F8 | 備份冰原 | v4 最終快照的壓縮包 | `tar` 與 `diff` 還原 |

只有七片也能開啟 `/` 的門，但只能選 `rebase` 或 `revert`。`merge` 與隱藏的 `fork` 需要八片。

### 核心謎團的四層

| 層 | 玩家以為 | 真相 |
| --- | --- | --- |
| 表層（Ch0–2） | Admin 失蹤了，lin 是他的徒弟 | lin 才是最後一任 Admin，Admin 是頭銜，持有 root 的人就是 Admin |
| 第二層（Ch3–4） | lin 想讓世界重啟 | lin 把 root 拆成八份，是為了不讓任何人再囤積 |
| 第三層（Ch5–6） | GC 想毀滅世界 | GC 是世界的免疫系統；Admin 沒有失蹤，是被回收了，因為 root 持有者什麼都想引用，連自己 |
| 核心（Ch7） | 集齊碎片就能當 Admin | 集齊碎片只會重啟循環。TICKET-0001 狀態是 `OPEN（reopened 4 times）`，四次重開就是四次輪迴 |

### 季末選擇

| 選項 | 效果 | 下一季主題 |
| --- | --- | --- |
| `merge` | 群島合併，root 改成 k-of-8 多簽（門檻式祕密分享），不再屬於任何一人 | 結盟季，可延伸成跨班級聯邦 |
| `rebase` | 有人接管 root，世界在新基底上重播，持有者必須登出 | 重播季，地圖洗牌，保留永久成就 |
| `revert` | 回滾到上一版，被回收的島復活，但本季領地清空 | 殭屍季，復活的島帶著 GC 的殘影 |
| `fork` | 隱藏選項：不改歷史，從現在分出一個新世界，舊世界原封不動 | 雙線季，每個玩家選擇留在哪條 branch |

### 知識卡總表

只有在分支裡發現的真相才算知識卡。八個島加一個支線，各有一個分支點，各給一張卡；集滿九張才能解鎖 `fork`。

| 卡 | 名稱 | 來源分支 | 用途 |
| --- | --- | --- | --- |

## 3. 探索主線 Ch0 到 Ch7

- 連線：每位新手各有一座副本燈塔，避免搶先與干擾。燈亮之後解鎖「值班室廣場」（共享區，可用 `who` 與 `wall`），而且全服有一個共同計數器：本季已亮燈的島嶼數。

- 連線：日誌是整個世界活動的縮影，裡面有其他玩家的登入、錯誤指令、渡海紀錄（暱稱化）。你 `grep` 得到隔壁隊伍的動向，這是偵察；別人也看得到你的。工單送到 OJ 正式判題。

### Ch2 〈權限堡〉`permfort`

目標：學會權限（`ls -l`、`chmod`、`id`、`sudo`），第一次組隊，拿到 F3，讀到憲章。

**開場。** 門衛 `sentry` 只會說一句話，但每次措辭不同，措辭本身就是提示：

```
op@permfort:~$ cd /fort/gate
sentry: Permission denied.
sentry: Permission denied (publickey).
sentry: Permission denied (quorum 1/3).
sentry: Permission denied (charter article 3).
sentry: Permission denied (you are not in the sudoers file.
        This incident will be reported.)
```

- `publickey`：你需要某把金鑰。
- `quorum 1/3`：這道門需要三個人同時在線。
- `charter article 3`：它在要你說出某一條憲章。

**開門的方法。** lin 的草稿（Ch0 取得的線索）引用了憲章第三條。玩家把這句話念給門衛：

```
op@permfort:~$ echo '任何持有 root 的操作，須有三名值班員同時在線。' > /fort/gate/intercom
sentry: ……Permission denied (quorum 1/3).
```

門衛承認了這句話，但要求三人到齊。三人在 30 秒內同時輸入 `unlock`，門才開。

**快題：**

| 編號 | 任務 | 學到 |
| --- | --- | --- |
| Q2-1 | 解讀 `-rwxr-x---`，誰能讀、誰能寫、誰能執行 | rwx 與 owner/group/other |
| Q2-2 | 把 `secret.key` 改成只有自己能讀寫 | `chmod 600` |
| Q2-3 | 找出所有人都能寫入的檔案 | `find -perm` |
| Q2-4 | 我屬於哪些群組 | `id`、`groups` |
| Q2-5 | 用 `sudo` 讀取被鎖住的 `.seal`（須三人在線） | `sudo` 與最小權限 |

**堡內的憲章**（kestrel，v2.4）：

```
第一條  島嶼由值班員守護，不屬於任何人。
第二條  日誌不得刪除，只得歸檔。
第三條  任何持有 root 的操作，須有三名值班員同時在線。
第四條  發現漏洞者，須先通報，後修補，再公開。
第五條  戰爭不得斷電。
第六條  GC 不得被封鎖。
第七條  root 持有者於季末必須登出，將 root 交還世界。
```

兩個小細節：第六條呼應 K1，kestrel 早就知道；第七條的修改時間比前六條晚了三個版本（`ls -l` 與 `stat` 能看出來），誰加的要到 Ch6 才揭曉。F3 就藏在 `/etc/charter.d/.seal`。

**憲章的版本（新增；上面的舊內容全部保留）：** 這份 kestrel v2.4 的七條，現在是《島嶼憲章》的 **Rev 1**，原文仍放在 `/etc/charter.d/v2.4.orig`。堡內現行的 `/etc/charter` 是 **Rev 5**（九條加附則）：每一條的第一句仍是 v2.4 的骨架句，後面長出的細則來自四次「出事後的修憲」（斷網算不算斷電、蛋糕事件、老王與颱風季、小周借用 root 遇到敲鐘）。所以 lin 草稿引用的第三條原句、念給 sentry 的口令、第六條呼應 K1、第七條比前六條晚三個版本，全部照舊成立。完整修訂史見附錄 A。笑點只放在憲章條文、harbor-master 的傳聞與日誌的 WARN 行，世界本身依然是冷的。

**分支點 B2：〈改寫憲章第三條〉（假設分支）**

回到 v2.4，把第三條改成「一名值班員即可」：

```
[sim] whatif/charter-solo
[sim] v2.5 ... v3.0   root 由單一值班員持有
[sim] v3.2            持有者掌控 11 座島
[sim] v3.4            OOM
[sim] 這是模擬。
```

合併後得到 **K2〈憲章為防囤積而生〉**。三人值班不是官僚，是設計。

**單人離線、多人離線、連線：**

- 單人離線：lin 的殘影加上兩名 NPC 值班員湊成三人。`ada` 愛問為什麼，`bo` 愛抄近路，兩人的性格會在後面章節反覆出現，可以被「記住」。
- 多人離線：用簽名檔完成法定人數。一份 `quorum.sig` 依序傳給三個人，各自簽名，最後合併；沒有同時在線的需求，但簽名順序會被記在 commit 裡。
- 連線：三名真人須在 30 秒內同時輸入 `unlock`，超時重來。找不到隊友可以掛單，24 小時沒人配對就由 NPC 補位。這是隊伍第一次合作儀式。

### Ch3 〈郵局島〉`mailisle`

目標：學會 `grep -l`、`grep -A`、`find`，讀懂 mbox 信件格式，揭露「Admin 是頭銜」，拿到 F4。

**開場。** `[PAGE] 郵局島：4,096 封信等待投遞，收件人全是 root。` 郵差 `postmaster` 有禮、囉嗦、守規矩：

```
postmaster: 歡迎光臨。請排隊。
postmaster: 依規定，寄給 root 的信只能由 root 簽收。
postmaster: 目前 root 不在。已經不在 4 個版本了。
postmaster: 您只想看？……那請到 spool 區，別亂動。
```

**檔案線索：**

```
/var/mail/spool/
├── root/          4,096 封，mbox 格式
├── returned/      被退件的信
└── dead.letter    寄不出去的信的墳場
/srv/post/
├── manifest.txt   收發紀錄
└── .stamp         郵戳（含 F4 的線索）
```

**快題：**

| 編號 | 任務 | 學到 |
| --- | --- | --- |
| Q3-1 | 找出所有 lin 寄出的信 | `grep -l` |
| Q3-2 | 數出總共有幾封信 | `grep -c '^Subject:'` |
| Q3-3 | 看一封信的主旨與後面五行 | `grep -A 5` |
| Q3-4 | 找出最近被動過的信 | `find -newer` |
| Q3-5 | 寄件人排行，找出誰只寫過一封 | `sort` 與 `uniq -c` |

**揭露。** 寄件人排行裡有四個只寫過一封信的名字：`moth`、`kestrel`、`ferrous`、`lin`，每人一封，全部寄給 `root`。他們就是四任 Admin。玩家在這裡第一次明白：Admin 不是一個人，是一個頭銜。

四封信的節錄：

- `moth`：「我給每座島一個名字。名字讓東西不容易被忘記。」
- `kestrel`：「我寫了憲章。我怕的不是壞人，是好人太久。」
- `ferrous`：「我引用了十一座島。GC 先回收的是我。」
- `lin`：寄了四次，每次都被退件，躺在 `dead.letter`。

```
From: lin
To: root
Subject: 給下一個值班員

不要拿 root。
——這封信我寄了四次，每次都被退件，因為收件人是 root，
而 root 在你拿到它之前，不存在。
```

F4 是這封信的附件。

**分支點 B3：〈lin 之夜：被刪掉的一行〉（回溯分支）**

玩家回到 lin 最後一夜的郵局，唯讀。NPC 看不見你，你只能看他的終端逐字重播：

```
（lin 打字）  不要拿 root。
（lin 打字）  我已經把它拆成八份，別把它找齊。
（lin 刪除）  ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
（lin 打字）  P.S. 燈我幫你留著。
（lin，對著空房間）  對不起，我只是想讓它不屬於任何人。
```

主線的信裡沒有那一行。合併後得到 **K3〈lin 把 root 拆成八份〉**，玩家的目標從此變成找齊八片碎片。

**單人離線、多人離線、連線：**

- 單人離線：信件內容固定，但寄件時間與郵戳會由種子微調；postmaster 的規矩對話較長，像一本有趣的服務條款。
- 多人離線：「漂流瓶」。玩家可以在存檔裡寫一封信放進 `spool`，下一個拿到這份存檔的人會讀到。這是最輕量的非同步合作。
- 連線：`spool` 是共享的。玩家可以寄信給未來的值班員，postmaster 負責審核，垃圾信會被退件。第一個找到 lin 最後一封信的隊伍會署名為「發現者」，寫進世界的 `git log`。

### Ch3.5 〈排程礦坑〉`cronmine`（支線，可選，但 `merge` 與 `fork` 結局需要）

目標：學會 `crontab` 語法、`at`、時間推理，拿到 F5，揭露賽季倒數。解鎖條件：在郵局 `dead.letter` 裡讀到那條 `0 0 29 2 *`。

**開場。** 礦工 `cron` 只在整點說話：

```
cron: 00:00。
cron: ……
cron: 01:00。
cron: 今天的排程沒有異常。
```

礦坑的每一條隧道是一條 crontab 條目，玩家要「讀懂」排程才找得到路。

**檔案線索：**

```
/var/spool/cron/crontabs/
├── root     大部分被註解掉
├── gc       GC 的排程
└── lin      只有一行註解
```

GC 的排程：

```
# 每天 02:00 例行掃描
0 2 * * *    /usr/sbin/gc --sweep
# 每四年一次的大掃除（F5 藏在這行後面的註解裡）
0 0 29 2 *   /usr/sbin/gc --full
```

**快題：**

| 編號 | 任務 | 學到 |
| --- | --- | --- |
| Q3.5-1 | 解釋 `0 2 * * *` 是什麼時候 | 五個欄位 |
| Q3.5-2 | 說出 `0 0 29 2 *` 下次什麼時候跑 | 閏年的推理 |
| Q3.5-3 | 看 GC 的 crontab | `crontab -l -u` |

- 多人離線：世界時鐘由存檔的 commit 數推進，每交換一次存檔推進一小時，傳存檔本身就是時間流逝。

### Ch4 〈網路群礁〉`routereef`

**快題：**

| --- | --- | --- |
| Q4-1 | 比較各島的延遲，找最近與最遠 | `ping` |

**單人離線、多人離線、連線：**

### Ch5 〈記憶體沼澤〉`heapswamp`

目標：學會 `ps`、`top`、`kill`、`ln`，理解引用與可達性，面對第一次 GC 的回收波，拿到 F7。

**開場。** 沼澤的蘆葦是記憶體區塊，水裡游的是行程。GC 在這裡第一次開口：

```
[gc] 我不是敵人。
[gc] 我只是把沒有人需要的東西，放回海裡。
[gc] 你上一次引用那座島，是什麼時候？
```

**Boss：回收波，三個階段。**

- 標記（mark）：GC 從根集合出發，標記所有可達的區塊。玩家有 60 秒用 `ln` 建立引用，讓重要的區塊變成可達。
- 清除（sweep）：沒被標記的區塊被回收。同時有洩漏的行程不斷吃記憶體，玩家用 `top` 找出異常，`kill` 掉它。誤殺重要行程會扣分。
- 壓縮（compact）：區塊被重新排列，路徑全變，玩家要用 `find` 與 `readlink` 重新找到自己的東西。

**快題：**

| 編號 | 任務 | 學到 |
| --- | --- | --- |
| Q5-1 | 找出最吃記憶體的行程 | `ps aux` 與排序 |
| Q5-2 | 即時觀察資源變化 | `top` |
| Q5-3 | 終止洩漏的行程，不誤殺 | `kill` 與訊號 |
| Q5-4 | 建立硬連結與符號連結，看哪個能保命 | `ln` 與 `ln -s` |
| Q5-5 | 看 inode 與連結數 | `ls -i` |

關鍵設定：硬連結增加引用計數，符號連結不會。lin 當年用的是硬連結，所以 GC 無法回收鑰匙碎片。

**工單 TICKET-0899〈誰會被回收〉（OJ，圖的可達性）：**

```
# TICKET-0899  [SEV-2]  沼澤引用圖已損壞，請預測哪些區塊會被回收
輸入: 引用邊清單與根集合
期望: 輸出所有會被回收（不可達）的區塊，由小到大
```

**GC 交出 F7：**

```
[gc] 這片碎片被引用過兩次。一次是 lin。
[gc] 一次是你。
[gc] 所以我沒有回收它。
```

這裡的「一次是你」指的是玩家在 Boss 戰裡建立的硬連結。是你的引用保住了它。

**分支點 B5：〈lin 與 GC 的談判〉（回溯分支）**

玩家回到 lin 最後一夜的沼澤，唯讀：

```
lin:   請把 root 回收掉。
[gc]   無法回收：refcount = 7,114,502。
lin:   誰在引用它？
[gc]   所有曾經登入過的人。
lin:   ……所有人。
[gc]   它不屬於任何一個人。它只是被每個人引用。
```

合併後得到 **K6〈root 的引用數來自所有人〉**。這是 `merge` 結局的核心論據。

**單人離線、多人離線、連線：**

- 單人離線：回收波是本地模擬，失敗不會掉區塊，只會被送回檢查點，並提示你開一條假設分支重打。
- 多人離線：隊員的存檔共同組成「根集合」。要讓一個區塊存活，必須有人在自己的存檔裡引用它，且存檔交換之後才算數，所以誰引用什麼要先講好。
- 連線：回收波是全服事件，在 02:00 準時降臨，沼澤島上所有隊伍同時面對同一波，`top` 顯示貢獻排行。失敗的隊伍真的失去區塊，成功的隊伍分享掉落的稀有檔案。

### Ch7 〈根目錄〉`/`

目標：拼回 root 金鑰，面對 INIT，在四個結局中選擇，或發現隱藏的第五條路。

**抵達。** `/` 是一扇門，門上有八個孔：

```
/
├── bin  etc  var  usr ...
├── dev/null/       黑潮，裡面有東西在動
├── home/lin/       lin 的家目錄（內容取決於你保存了多少遺物）
└── root/           門後
```

**拼金鑰。** 八片碎片的檔案本身沒有順序，順序藏在建立連結的時間：用 `ls -ltr` 依修改時間由舊到新排序，再 `cat` 串接成 `root.key`。順序錯了，門只會回 `Permission denied (quorum 0/8)`。

**lin 的最後一段 `.bash_history`**（在 `/home/lin` 裡完整出現）：

```
kill -STOP 1
kill: (1): Operation not permitted
kill -9 1
kill: (1): Operation not permitted
kill -9 1
kill: (1): Operation not permitted
logout
```

lin 想停下 INIT，打斷循環，三次都失敗。在真實 Linux 裡，同一命名空間內的行程對 PID 1 送 SIGKILL 會被核心忽略（除非它自己裝了處理器），細節以 `man 7 pid_namespaces` 為準。這個設定的意義是：INIT 不是敵人，只是不能被停下的東西。然後他遵守第七條，登出，沒有人引用他，於是被回收。

**INIT 的最後自白：**

```
[init] 我必須告訴你一件事。
[init] TICKET-0001 不是 lin 留下的，是我開的。
[init] 內容只有一個問題。
```

```
# TICKET-0001
報告人: INIT (pid 1)
狀態:   OPEN (reopened 4 times)
指派:   root
問題:   這個系統，還需要繼續存在嗎？
```

```
[init] 我回答不出來。四次，我都把它重開了。
[init] 這一次，我想交給你。
```

**遺物引用（選擇性，沒有提示）。** 每章有一件 lin 的遺物，玩家可以用 `ln` 把它「引用」下來，而不只是讀過。這個動作沒有任何獎勵，INIT 也不會提醒。

| 章 | 遺物 |
| --- | --- |
| Ch0 | `notes/01-first-night.txt` |
| Ch1 | `/srv/harbor/lin-ticket.md`，lin 當年解過的一張工單 |
| Ch2 | `/etc/charter.d/amend-7.draft`，第七條的草稿 |
| Ch3 | `dead.letter` 中那封信的副本 |
| Ch3.5 | `crontabs/lin` 裡唯一的註解 |
| Ch4 | `/var/log/hop-notes/.author`，墓誌銘作者的簽名 |
| Ch5 | `~/lin/.plan`：「燈我幫你留著。」 |
| Ch6 | `v4-final/README` |

（新增）Ch2 的 `/etc/charter.d/` 另有 `amend-10.draft`（第十條草案）與 `v2.4.orig`（Rev 1 原文），與 `amend-7.draft` 並存；它們是線索檔，不計入八件遺物。

保存的遺物數量決定 `/home/lin` 在結局裡的樣子：

- 0 到 3 件：只剩 `.plan` 一行字。
- 4 到 7 件：INIT 會轉述 lin 的一段話。
- 8 件：lin 完整登入，成為最後一個 NPC，在結局裡與你並肩站著：「你比我想的晚到。不過……燈是亮的。這樣就夠了。」

這個機制的意思是：GC 只回收沒人需要的東西，而「記得」就是引用。

**分支點 B7：〈另一種結案〉（平行分支）**

在門前，玩家可以把四個結局各開一條平行分支，完整走完，用 `tag` 收藏，再回到主線做真正的選擇。看完結局之後的世界，合併後得到 **K8〈另一種結案〉**。

**四個結局與一個隱藏結局：**

| 結局 | 條件 | 發生的事 | 對下一季的影響 | 對應陣營 |
| --- | --- | --- | --- | --- |
| `rebase` 重新開機 | 7 或 8 片碎片 | 你持有 root，世界在新基底上重播。依第七條，你必須在季末登出，家目錄被回收，名字留在 `git log` | 地圖洗牌，保留永久成就 | 核心 Kernel |
| `revert` 回滾 | 7 或 8 片碎片 | 世界回到 v4.9，被回收的島一座座亮燈復活，但本季領地清空，復活的島帶著 GC 的殘影 | 殭屍季 | 常駐 Daemon |
| `merge` 共管 | 8 片碎片，K4 與 K6 | 八片碎片重新綁給八位守鑰者，root 變成 k-of-8 多簽，refcount 等於所有玩家。GC 回收不了它，世界穩定，但任何改動都需要合作 | 結盟季，可延伸成跨班級聯邦 | 路由 Router |
| `fork` 分叉（隱藏） | 8 片碎片，K0 到 K8 全部九張 | 你不開門，改在門前 `git checkout -b v5.1-fork`。舊世界原封不動繼續運轉；新世界是 v5.0 的副本，八片碎片分給所有人，沒有人持有 root | 雙線季，每個玩家選擇留在哪條 branch | 外殼 Shell |

fork 結局的最後畫面：

```
[init] 你沒有回答我的問題。
[init] 你開了另一個問題。
[init] ……我想試試。

TICKET-0001  status: OPEN -> FORKED (see v5.1)
```

這是整個故事的主旨：歷史沒有被改變，只是多了一條可以走的路。

**賽季終了：名人堂。** 無論選了哪個結局，最後一個畫面都是世界的 `git log`：

```
commit 7f3a9c1 (HEAD -> main, tag: v5.0-final)
Author: op-<你的暱稱> <root@archipelago>
Date:   二月二十九日 00:00

    close TICKET-0001: <你選的結局>

commit c01d5ee (tag: v4.9)
Author: lin

    don't take root
```

**單人離線、多人離線、連線：**

- 單人離線：最終選擇就是你的結局。NPC `ada` 與 `bo` 站在你身後，反應隨選擇改變。四個結局與隱藏結局都可以在平行分支裡看完。
- 多人離線：結局用投票簽名決定。每位隊員用自己的存檔投一票（寫進 commit），多數合併；平手由最後簽名者決定。fork 需要全隊知識卡聯集覆蓋 K0 到 K8。
- 連線：全服季末投票用 `vote`，三選一，fork 是隱藏選項，需要全服的知識卡聯集覆蓋 K0 到 K8。結果寫入 `main`，所有參與者署名。少數派可以選擇「分流」進入 fork 分支，也可以留在主世界。投票截止就是閏日 00:00。

## 4. 白帽紅隊學院

學院的主題只有一句：先被修，才算贏。玩家扮演經授權的白帽，在虛構的演習島找出弱點、寫成報告、推動修補；所有漏洞都是教學用的玩具，每一個都附帶偵測與修補方式。

### 設定

- **Ops Academy** 位於燈塔島的舊倉庫 `/academy/`，起因是憲章第四條：發現漏洞者，須先通報，後修補，再公開。
- **演習群礁 `drillreef`**：七座由 NPC 經營的虛構島嶼，專供練習，與主世界的島嶼完全隔離。
- **入學條件：** 完成 Ch2，且守護夜班達到「夜班員」等級。先學防守，再學攻擊。
- **人物：** 導師 `wren`（退休的紅隊老手，乾、愛開玩笑）；同期 `sable`（野心大、愛搶第一）；同期 `pip`（容易緊張，但報告寫得最好）；系統考官 `proctor`（只負責評分，不說話）。

### 白帽守則 Ops Code

1. 只在演習島與被授權的島嶼動手。
2. 發現即回報，先修後揭。
3. 不傷活人的 uptime。
4. 每次展示攻擊都要附上偵測與修補方式。
5. 留下紀錄，接受審計。

### 一案的流程

簡報 → 偵察 → 發現 → 決策 → 報告 → 評分。其中「決策」是故事的重心：玩家要選怎麼處理這個發現。

| 選項 | 內容 | 在演習島上的後果 |
| --- | --- | --- |
| 通報 | 先私下告知島主，等修補後才公開 | 島主信任上升，修補完成，案件結案 |
| 暗中保留 | 不說，把發現留著備用 | 島主繼續暴露在風險裡；過一段時間，別人先發現並造成損失 |
| 直接公開 | 不通報，直接張貼 | 全島恐慌，島主來不及修補，被迫臨時下線 |

玩家永遠可以先開兩條假設分支，模擬「如果我不說」與「如果我公開」，看完後果再回主線選擇。合併後得到一張「案例教訓」。

**報告模板（每案必交）：**

```
標題:
摘要:       一句話說明發現了什麼
影響:       誰會受到什麼影響
風險等級:   低 / 中 / 高，並說明理由
重現步驟:   （演習島專用，只寫玩具環境的步驟）
偵測方式:   藍隊怎麼發現它
修補建議:   怎麼修，修完怎麼驗證
時間軸:     發現、通報、修補、公開的時間
```

**評分：**

| 項目 | 說明 |
| --- | --- |
| 發現 | 找到的弱點是否完整，有沒有誤報 |
| 重現的準確度 | 步驟是否讓別人能照著重現 |
| 修補建議的品質 | 是否可行、是否驗證過 |
| 回報速度 | 發現到通報的時間 |
| 負責任揭露 | 選「通報」的案件，總分乘以 1.5 |

### 七案

**案 1 〈便利貼〉**（島主 `mina`）

- 情境：mina 一個人守一座島，把管理密碼貼在公告欄旁邊，方便大家記得。
- 玩具漏洞概念：機密放在明處。
- 偵察：`cat /srv/board/notice.txt`。
- 修補：移除、輪換密碼、改用不外露的存放方式。
- 人物線：mina 其實很怕被責備。wren 在簡報時說：「報告是寫給人看的，不是寫來打臉的。」第一課是同理，不是技術。

**案 2 〈歷史的回聲〉**（島主 `oto`）

- 情境：oto 話很多，把什麼都講給終端聽，包括不該講的。
- 玩具漏洞概念：機密洩漏在指令歷史與日誌裡。
- 偵察：`cat ~/.bash_history`、`grep -r 'key' /var/log`。
- 修補：清除並輪換、改用環境變數或專用的祕密管理。
- 與主線的連結：lin 的 `.bash_history` 也是這樣被讀出來的，玩家會在這案意識到自己讀人家的歷史，其實就是一次偵察。

**案 3 〈777〉**（島主 `rue`）

- 情境：rue 嫌設定權限麻煩，把備份目錄全部打開，說「方便同事」。
- 玩具漏洞概念：過寬權限。
- 偵察：`ls -l` 看到 `drwxrwxrwx`。
- 修補：`chmod`，套用最小權限。
- 與主線的連結：Ch2 權限堡的功課在這裡變成別人家的問題。

**案 4 〈過期的備份〉**（島主 `jax`）

- 情境：jax 記憶力超強，從不丟東西，舊備份堆了七年。
- 玩具漏洞概念：舊備份仍可存取，裡面有早已作廢卻還能用的舊密碼。
- 修補：備份加密、定期清理、資料生命週期管理。
- 主題呼應：「什麼都留著」就是 ferrous 的影子。這案的對白會讓玩家想起囤積。

**案 5 〈會自己跑的東西〉**（島主 `kiri`）

- 情境：kiri 的自動任務腳本，任何人都能改。
- 玩具漏洞概念：寫入權限過寬的排程腳本，會讓一般使用者的修改被更高權限的任務執行。
- 偵察：`crontab -l`，再用 `ls -l` 看腳本權限。
- 修補：收緊權限、把腳本放在受保護的目錄。
- 與主線的連結：Ch3.5 排程礦坑。學員會對 `0 0 29 2 *` 那條排程多看一眼。

**案 6 〈輸入框裡的陷阱〉**（島主 `dov`）

- 情境：公告留言板把使用者輸入原樣顯示。
- 玩具漏洞概念（極簡）：輸入沒有被檢查，一段看起來像「版面指令」的字被當成內容執行，結果整個公告欄被弄亂。
- 修補：驗證輸入、轉義輸出。
- 說明：這案只教概念，演習島內的玩具留言板用的是自創的標記，不對應任何真實語法。

**案 7 〈最後一封報告〉**（島主 `elm`，紫隊演習）

- 情境：前六個島主聯手舉辦演習，邀請紅隊與藍隊合作。紅隊（你）交出前六案的發現，藍隊（守護夜班的玩家）負責偵測，雙方一起整理出一份修補路線圖。
- 最終關卡：一場「GC 掃描日」。GC 的探測（Ch1 的 `/gc/probe`）被當成壓力測試，驗證各島的修補是否有效。
- 揭露：wren 年輕時是 ferrous 的紅隊顧問。他發現過 `isle-013`（紅樹林）的弱點，卻選擇留著不說。後來那座島失去信任，被回收。墓誌銘寫的「沒有人回信」，其實是他沒有回信。這就是白帽守則的由來。

```
wren: 我沒有利用它。
wren: 我只是……沒說。
wren: 後來我才知道，這兩件事，在受害的人眼裡沒有差別。
```

### 學習路徑與晉升

學員 → 見習紅隊 → 紅隊員 → 資深。資深的最後一步是**出題**：玩家可以設計自己的演習島案件，附上偵測與修補，經審核後進入題庫給後來的人練習。出題者就是白帽的最高階段。

### 單人離線、多人離線、連線

- 單人離線：wren 以對話批改報告（規則式檢查表加範例報告對照），NPC 島主的反應固定，演習島每次相同。
- 多人離線：互相審閱。存檔交換時，報告會放進對方的 `review/` 收件匣，兩人輪流當對方的藍隊並給評分，再由 wren 的基準分校正。
- 連線：每週開放一座演習島，全服同時進行。首位通報者署名為「發現者」，進入名人堂的 `SECURITY.md`。賽季中有「紅藍對戰日」：紅隊在演習島製造事件，藍隊同時在守護夜班裡處理，你看得到他們的偵測時間，他們看得到你的手法。這是 Attack-Defense CTF 的安全教學版。

## 5. 守護夜班（藍隊）

夜班是一個關於「有人醒著」的故事：玩家扮演燈塔的守夜人，從 22:00 守到 06:00，用日誌、權限、備份和一點耐心，讓島在天亮前還在原地。每一夜是一個獨立事件，七夜串成一條小弧線。

### 設定

- **班次：** 世界時間 22:00 到 06:00。02:00 是 GC 的例行掃描，正好落在班次正中央，整晚的緊張都繞著這個時刻。
- **同事：** `ups`（值班長，一個快沒電的老 AI，說話像電池餘量：「電量 63%，我還撐得住。」）；`fan`（散熱員，容易緊張，總是先道歉）。
- **工具：** `last`、`grep`、`sort`、`uniq`、`df`、`du`、`chmod`、`kill`，加上遊戲內的 `fw`（模擬防火牆，`fw block`／`fw allow`）、`log`（讀系統日誌）與 `restore`（從備份還原）。
- **等級：** 夜班員（解鎖白帽學院）→ 值班長 → 守夜人。

### 一夜的事件波

| 時段 | 強度 | 內容 |
| --- | --- | --- |
| 22:00 到 00:00 | 輕 | 一個明顯的小故障，用來暖身並交代背景 |
| 00:00 到 02:00 | 中 | 一個需要查證的異常，通常有一個誤殺陷阱 |
| 02:00 到 04:00 | 重 | GC 掃描加上主要事件，雜訊與訊號混在一起 |
| 04:00 到 06:00 | 收尾 | 修復、驗證、寫事後檢討 |

### 計分

| 指標 | 意義 |
| --- | --- |
| 偵測時間 | 事件發生到你發現的時間（MTTD） |
| 回應時間 | 發現到處置完成的時間（MTTR） |
| 誤殺率 | 擋掉或殺掉正常東西的比例，誤殺越多扣越多 |
| 完整度 | 天亮時島嶼的完整度 |
| 檢討品質 | 事後檢討是否找到系統根因 |

### 七夜

**夜 1 〈靜默的燈〉**

- 事件：22:41，`lamp.service` 停了。
- 查證：`log lamp` 顯示寫入失敗，原因是日誌磁碟寫滿。
- 重點：只重啟燈是治標；根因是日誌沒有輪替。
- 對白：`ups`：「燈會熄兩次。第一次是故障，第二次是你沒找到原因。」

**夜 2 〈敲門聲〉**

- 事件：大量連線嘗試。其中 `198.51.100.23` 在三十分鐘內登入失敗四百次；另一個 `10.7.0.2` 每晚 02:00 準時來訪。
- 陷阱：兩者都像攻擊，但後者是 GC 的探測。
- 知識卡 K1 的作用：有 K1 的玩家知道封鎖 GC 會讓它升級，不會誤殺；沒有 K1 的玩家封了就會看到 `[gc] escalating`，掉三倍區塊。
- 重點：區分雜訊與訊號。

```
[log] 00:12:03 auth failure from 198.51.100.23 (x400 in 30m)
[log] 02:00:00 GET /gc/probe from 10.7.0.2 ua=gc/1.0 (sweep)
[ups] 電量 71%。兩個都是敲門聲。只有一個是敲錯門。
```

**夜 3 〈多出來的使用者〉**

- 事件：03:12，`/etc/passwd` 出現新帳號 `lamplighter`，上次登入是 41 天前。
- 真相：那是 lin 寫的小服務，在燈亮起時自動醒來。是玩家在 Ch0 點亮的燈叫醒了它。
- 決策：刪除、保留、限縮。最佳解是保留但收到最小權限。刪除會失去一件遺物（影響 Ch7 的引用數）。
- 重點：帳號稽核、休眠帳號的風險，以及「最小權限優於刪除」。

**夜 4 〈滿載〉**

- 事件：磁碟使用率 97%，一個行程不斷吐出核心傾印檔。
- 查證：`df -h`、`du -sh * | sort -h`、`find -size +100M`。
- 陷阱：憲章第二條規定日誌不得刪除，只得歸檔。直接 `rm` 會被扣分，正確做法是 `tar` 壓縮歸檔再釋放空間。
- 重點：容量監控與合規處置。

**夜 5 〈錯的備份〉**

- 事件：設定檔被改壞，服務起不來。最近的備份是六天前。
- 決策：整份還原（丟掉六天資料，最快）、手動修（風險高）、只還原設定檔（最好，但要先用 `diff` 找出壞掉的那一處）。
- 重點：恢復點目標與恢復時間目標（RPO 與 RTO），以及「沒被還原過的備份不算備份」。

**夜 6 〈內部〉**

- 事件：`fan` 調錯散熱曲線，伺服器過熱降頻。
- 情感：`fan` 一直說「對不起，是我的錯」。
- 重點：無責備的事後檢討。評分規則直接獎勵「找到系統根因」（例如：改設定沒有第二個人複核、沒有變更前的預覽），扣分「把責任歸給個人」。

**夜 7 〈回收夜〉**

- 事件：白帽學院舉辦紫隊日，紅隊學員在 GC 掃描期間對主島做一次已公告的模擬入侵。
- 難點：GC 的掃描產生大量讀取雜訊，真正的異常只有三個，藏在裡面。
- 知識卡的作用：K1（別擋 GC）、K5（孤立節點先被回收，防守要保連線）都會用上。
- 重點：在雜訊裡找訊號，並把處置結果回饋給紅隊，形成紫隊循環。

### 事後檢討模板

每夜結束必須交一份，沒有評分的捷徑，只有範例對照：

```
# 事後檢討：<事件名>
日期與時長:
影響:        誰、什麼服務、多久
時間軸:      發現、處置、恢復各是幾點
偵測:        怎麼發現的，花了多久
根因:        系統層面，不指名個人
做得好的:
可以更好的:
改進項目:    （負責人 / 期限）
```

規則寫在模板頂端：**只問「系統為什麼讓這件事發生」，不問「是誰」。**

### 分支：桌上演練

每夜結束後，玩家可以 `git checkout -b whatif/replay-N`，回到事件發生前五分鐘，改變決策再跑一次。這就是真實世界的桌上演練（tabletop exercise）。回放練習不消耗時間燃料，也不計分。

### 單人離線、多人離線、連線

- 單人離線：夜班是回合制，每回合一小時，可暫停；事件序列由存檔種子生成。向 `ups` 問「現在狀況」會得到摘要，像一個老同事在耳邊低語。
- 多人離線：**交班**。同一份存檔由不同人輪流值班，換班時必須寫一張交班單，下一個人看不到你的腦袋，只看得到交班單。交班單的品質直接影響下一班的偵測時間，這是溝通與寫作的訓練。
- 連線：24 小時真實排班。隊伍排值班表，事件在你離線時也會發生，醒來看 `last`、`uptime` 與 `log` 的戰報，隊友的處置紀錄就是你的事後檢討素材。呼叫機（pager）正是 INIT 在主線裡用的同一個機制。可以設定安靜時段，那段時間不收呼叫，由隊友代班，這也是在教健康的值班文化。

## 6. 解題工單短篇

每一道 OJ 題目都被包成一張工單，工單本身就是一篇三百字的小說：題面是工單的語言，測資是工單附的檔案，判題結果是系統的日誌。題目不變，包裝可換，這讓內容量不是瓶頸。

### 工單格式

```
# TICKET-<編號>  [SEV-<1 到 4>]  <標題>
報告人:   <NPC>          狀態: OPEN          獎勵: <區塊數> + <線索>
背景:     <三到五句，一個小故事>
輸入:     <格式，用工單語言>
期望:     <題目要求>
約束:     <時限、記憶體>
範例:     <輸入與輸出>
彩蛋:     <一個與主線有關的小細節，選填>

```

嚴重度即難度：SEV-4 約 5 到 10 分鐘，SEV-3 約 20 分鐘，SEV-2 約 40 分鐘，SEV-1 是島的 Boss 題，60 分鐘以上。獎勵按通過率給部分分：測資過了一半，就拿一半的區塊。

### 把題目換皮的五個步驟

1. 抽出題目的核心：資料結構、演算法、輸入輸出格式。
2. 選一座島，讓題目屬於它的主題。
3. 把輸入輸出改寫成日誌、信件、排程的語言，不改格式。
4. 加一個與主線有關的彩蛋，一個就好。
5. 範例、測資、時限原封不動，只換敘述與判題文案。

示範：把「兩數之和」換成權限堡的鑰匙櫃。

```

        背景: sentry 的鑰匙櫃裡每把鑰匙有一個齒數。門只認兩把鑰匙的齒數
              加起來剛好等於鎖的需求。
        輸入: 每把鑰匙的齒數，以及鎖的需求
        期望: 輸出是哪兩把鑰匙（編號）

```

## 7. 搶島戰史與陣營戰

搶島模式把賽季寫成一場十二週的戰爭，戰場是浮在封包海上的八座島，敵人不是 GC，而是另外三個對 root 有不同想法的陣營。每個陣營都以為自己在救世界，而它們想要的結局，剛好就是季末的四個選項。

### 領地規則速覽

- 每座島是 8×8 共 64 個區塊，每塊有擁有者與完整度（0 到 100）。
- 快題（終端機小謎題，1 到 3 分鐘）：佔領中立區塊、回復完整度。
- 慢題（OJ Boss，20 到 60 分鐘）：每島一題，隊伍中任何人 AC，全隊成為島主一週，可收稅，可改島的登入歡迎詞。
- GC 每日 02:00 掃描：沒人互動的區塊完整度下降，歸零就被回收成中立。
- 領地越大，維護成本越高，衰退越快；新隊伍有種子區塊。
- 每隊每週一次八小時的維護窗口（無敵），須提前預約。
- 進攻：解一題難度不低於對方防禦值的攻擊工單。防守方靠完整度、修補等級與 Warden 寫的測資強度。

- **同盟條約：** 需要雙方領袖簽名（遊戲內是兩名隊長各自簽署一個 commit）。毀約等於對條約 `git revert`，會留下永久記錄，名聲受損。

- **賞金：** 全服公告某件事，例如「第一個找到 `lin` 的第三件遺物」，獎勵是署名，不是金錢。

## 8. 其他模式的故事

五個模式共用同一個世界與同一套引擎，各有自己的故事與節奏。它們不需要完成主線也能玩，但都會暗中回應主線的某個秘密。

### 8.1 管線接力〈三條支流〉

三個人，三個角色，一條管線：A 是**收集者**，從島上拉出原始資料；B 是**過濾者**，只留下有用的；C 是**彙整者**，把結果算成答案。A 的輸出檔是 B 的輸入，B 的輸出檔是 C 的輸入，就像 `A | B | C`。

**故事。** 世界裡有一個傳說：三條支流匯流的地方，會浮現一座不在地圖上的島。三個案件，三次匯流，每次拼出一部分座標。

| 案 | A 收集 | B 過濾 | C 彙整 | 輸出 |
| --- | --- | --- | --- | --- |
| R1 〈第一道水〉 | 從日誌港拉出 access.log | 只留 02:00:00 的請求 | 統計 GC 探測次數 | 一個數字 |
| R2 〈分流〉 | 從郵局拉出所有信件標頭 | 只留寄件人欄位 | 去重並排序 | 四位 Admin 的名單 |
| R3 〈匯流〉 | 從群礁拉出 ping 紀錄 | 剔除已回收節點 | 計算最短路 | `isle-000` 的座標 |

**規則：介面契約。** 比賽開始前有三分鐘的「契約協商」，三個人用 `wall` 約定輸出檔的格式：欄位分隔符號、編碼、換行、空檔怎麼處理。格式不一致，下游會直接收到 `Broken pipe`，整條鏈斷掉。這是在教 API 設計與溝通。

**揭露。** `isle-000` 是 `moth` 建的第一座島，只有一盞燈，是歷代 Admin 的「留言信箱」。這裡有 moth 的實驗筆記和那隻 bug 的完整故事，是一座純收藏、不影響結局的小寶庫。

- 單人離線：你輪流扮演三個角色，另外兩個由 `ada` 與 `bo` 代打，你要為自己的下一棒寫好契約。
- 多人離線：把存檔當接力棒，三個人依序接手，上一棒的輸出檔放進下一棒的 `inbox/`。
- 連線：三人即時組隊，計時賽。契約越乾淨，加成越高。

### 8.2 MUD 地城〈`/usr/lib` 地城〉

純文字冒險：房間就是目錄，怪物是行程，道具是檔案。指令就是動詞。

| 指令 | 遊戲動詞 |
| --- | --- |
| `ls` | 環顧四周 |
| `cd` | 前往 |
| `cat` | 閱讀 |
| `kill` | 攻擊 |
| `chmod` | 附魔 |
| `mv` | 搬運 |
| `man` | 向 NPC 請教 |
| `grep -E` | 咒語（正規表達式法師專用） |

**故事。** `libc`，所有程式賴以運轉的函式之心，被某種東西啃壞了。世界上的程式一個個開不起來。你要深入 `/usr/lib`，找回它。

```
/usr/lib/
├── libc/       一樓：圖書館，書名全是函式名
├── libm/       二樓：數學神殿，每道門是一道小題
├── python3/    蛇窩，會說話但囉嗦
├── systemd/    機房，齒輪聲不斷
└── .hydra/     封印的門
```

- **一樓 libc 圖書館：** 用 `grep` 在書架間找出被撕走的那一頁。
- **二樓 libm 神殿：** 每道門是一道小型 OJ 題，答對才開。
- **三樓 `.hydra`：** Boss，**九頭蛇**。牠每回合分裂成兩倍：

```
[hydra] 我是 1 個。
[hydra] 我是 2 個。
[hydra] 我是 4 個。
```

硬打只會越打越多。正解是追查牠的親行程（`ps -o ppid`），從源頭 `kill` 掉，或者先用 `ulimit` 限制它能生出的數量。這是在教行程樹與資源限制。

**孤兒行程與殭屍行程。** 地城裡也有遊蕩的孤兒（沒有父行程）與殭屍（已死但還佔著位置）。孤兒需要被領養，殭屍需要有人回收，前者是任務，後者會在第二季的殭屍季重新登場。

- 單人離線：標準單人冒險，存檔點在每間房。
- 多人離線：每個人的存檔會在房間留下「遺骸」（死亡位置與道具），下一個走進同一間房的存檔會看到，像是在別人的失敗上前進。
- 連線：四人隊伍，用 `tmux` 共享畫面。職業：前衛（kill）、補師（restore）、偵察（find）、法師（正規表達式）。

### 8.3 偵探懸案〈封包海懸案〉

純調查模式。每週一案，像用指令破案的推理小說。通關不是 AC，而是交出一個「旗」，並附上證據鏈。

| 案 | 標題 | 核心問題 |
| --- | --- | --- |
| 1 | 誰把燈關了 | 燈塔的燈為什麼在 41 天前熄滅 |
| 2 | 消失的 IP | 昨天攻擊的 IP 從日誌裡消失，誰動了手腳 |
| 3 | 第十二把鑰匙 | 鑰匙櫃清單有十二把，實物只有十一把，缺的那把在哪 |
| 4 | 同時在兩地 | 一個帳號同時從兩座島登入，這不可能 |
| 5 | 最後一個值班員 | 在 lin 之前，最後一個值班的人是誰 |

**案 1 的證據鏈（示範）：**

| 步驟 | 線索 | 指令 |
| --- | --- | --- |
| 1 | 燈在 02:00:00 被停掉 | `grep lamp logs/lamp.log` |
| 2 | 停掉的人是 uid=lin | 同上，行末 |
| 3 | 那時有誰登入 | `last` |
| 4 | lin 當晚打了什麼 | `cat ~/.bash_history` |
| 5 | 交叉比對時間戳 | `grep -n` 與 `diff` |
| 旗 | 燈是 lin 手動關的，不是故障 | `FLAG{lin-02:00-manual}` |

案 4 的謎底：兩座島的時鐘偏差十七分鐘，所謂「同時」只是時區設定錯誤，這會在連線模式中呼應 GC 時區的設計。案 2 的謎底：日誌沒有被刪（憲章第二條），只是被歸檔進 `rotated/*.gz`。

**玩法：** 每案有一份嫌疑人名單（`getent passwd`）、不在場證明（`last`）、動機與證據。玩家維護一份 `suspects.md` 排除法筆記，最後提交旗與證據清單。評分看三件事：是否找到旗、證據鏈是否完整、用了幾個指令（越少越優雅）。

- 單人離線：案件包是一份檔案，全部證據在本機。
- 多人離線：**拼圖偵探**。三個人各拿到三分之一的日誌，必須交換存檔才能湊出完整證據，而不同存檔裡的證詞可能互相矛盾，要靠合併衝突解開。
- 連線：每週三開案，週日截止。有排行榜，但解案後可以公開「探案筆記」互相觀摩，並有防劇透的鎖定期。

### 8.4 經營日誌〈燈塔機房〉

放置型經營。你是燈塔機房的管理員，每天一則日誌，一邊維運一邊看著小小的機房長大。

- **資源：** 電力、冷卻、備品、信任。
- **員工：** `ups`、`fan`、`lamplighter`。
- **升級樹：** 儲存、網路、備援、監控、文件。
- **政策卡：** 自動備份、輪替值班、定期稽核、公開事後檢討。每張卡有成本，也有副作用。

```
Day 17  晴。電力 71%，冷卻 64%。
        fan 說散熱曲線需要調整，ups 說電池還能撐。
        收到一封信，寄件人 lin，日期是 41 天前。
        決定：今天不擴建，先做備份。
```

**六個月六章：** 開張、第一次擴建、第一次大停電、鄰島來信求助（貿易）、大掃除前的稽核、閏日。

**勝利條件：** 閏日時被至少兩座鄰島引用（呼應 K4 與 K5：被引用才不會被回收，連線度高才不會先死）。所以經營的核心不是賺最多，而是「讓別人需要你」。

- 單人離線：鄰島是 NPC，依你的決策決定要不要連你。
- 多人離線：用寫信（存檔交換）貿易與求助。
- 連線：其他玩家真的可以選擇引用你的燈塔，這會建立一張真實的互相引用的社交圖。離線時日誌照常進行，GC 的衰退也照常計算。

## 9. 三種遊玩層級的差異與分支地圖

同一份故事用三種方式玩：單人離線追求密度與自由，多人離線追求協作與交換，連線追求競爭與共同記憶。三者共用同一套引擎與存檔格式，所以玩家可以在層級之間遷移。

### 差異總表

| 面向 | 單人離線 | 多人離線 | 連線 |
| --- | --- | --- | --- |
| 存檔 | 本機 `save/` 資料夾（commit 紀錄） | 存檔檔案可 push／pull：檔案、剪貼簿字串、區網 | 世界伺服器保存，客戶端只送指令 |
| 時間 | 回合制，可暫停，時鐘可加速 | 世界時鐘隨存檔的 commit 數推進 | 與真實時間同步，GC 每日 02:00 |
| 分支 | 同時最多 5 條，無成本 | 每人各開分支，合併時處理衝突 | 消耗時間燃料，每日補充 3 單位，全隊共享 |
| 故事密度 | 最高：完整對話樹、全部支線、可無限重來 | 高：再加上他人留下的信、遺骸與足跡 | 中：主線相同，但有共享世界的干擾與事件 |
| NPC | 由 AI 與劇本驅動，`ada`、`bo` 補位 | 同單人，加上存檔裡別人留下的痕跡 | 真人為主，NPC 補位與撐場 |
| 真相 | 沒有競爭，永遠完整 | 發現者署名在存檔交換時才生效 | 搶先署名，寫進名人堂 |
| GC 與領地 | 模擬，失敗送回檢查點 | 存檔合併時結算 | 真實損失，真實回收 |
| 合併衝突 | 只需確認 | 協作謎題 | 協作謎題加上全服投票 |
| 判題 | 本機判題器 | 判題簽名收據 | 正式 OJ 加相似度檢查 |
| 信任與作弊 | 不排名，作弊無意義 | 簽名收據與雜湊鏈降低竄改 | 伺服器重放驗證，唯一可排名的層級 |
| 適合 | 初學、通勤、離線、作品集展示 | 朋友、讀書會、課堂分組作業 | 社群、賽季競賽、班級學期 |
| 技術要求 | 靜態網頁加本機引擎 | 同上，加存檔匯出匯入與簽名 | 世界伺服器、OJ、重放驗證 |

### 層級之間的遷移

存檔是 commit 紀錄，遷移靠重放：只要引擎版本一致，兩邊就算得出同一個世界。

| 從 | 到 | 保留 | 不保留 |
| --- | --- | --- | --- |
| 單人離線 | 連線 | 主線進度、知識卡、分支、遺物引用 | 領地、區塊、AI 賽季戰績 |
| 連線 | 離線匯出 | 主線進度、個人知識卡（快照） | 即時事件、領地、他人署名 |
| 多人離線 | 連線 | 各人進度，以及合併後的知識卡聯集 | 離線期間的時間推進 |

### 三層共用的設計規則

- 一個引擎，兩個宿主：瀏覽器本機與伺服器跑同一份程式，所以重放結果相同。
- 所有隨機由種子決定，種子寫在存檔裡，不使用系統亂數。
- 所有事件都是 commit，介面只是 commit 的檢視。
- 劇情文字與規則分離：文字放資料檔，規則放引擎。

### 分支地圖

主線有九個站，每站一個分支點，分支分三種類型。知識卡一路帶回主線，最後匯入四個結局；隱藏的 fork 需要九張卡全部集齊。
