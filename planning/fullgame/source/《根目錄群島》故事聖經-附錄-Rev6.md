## 1. O-N02：Ch7 八空格輸入規則

**裁定**：沒有「八格」介面。

玩家用 `ls -ltr` 看到八片碎片檔案的順序，再自己在終端機打 `cat a b c d e f g h > root.key`（檔名依 mtime 由舊到新手打），最後執行 `unlock root.key`。錯誤順序時門回 `Permission denied (quorum k/8)`，k ＝ 正確前綴的長度；完全錯誤時回 `quorum 0/8`。

**理由**：完全是真 Bash 行為，不需要 `$(...)` 等模擬器不支援的語法；鍵盤與讀屏皆可用，無障礙問題直接消失。

**與聖經關係**：聖經 Ch7 已有「八片碎片、順序藏在硬連結建立時間、cat 串接成 root.key」的敘事；本附錄將其具體化為可執行的終端機操作，不改聖經正文。

## 4. O-N08：Ch2 草案全文的遮蔽策略

**裁定**：不遮蔽 `amend-10.draft`。

「檔案可讀」與「理解」分開：Ch2 讀得到 `/etc/charter.d/amend-10.draft`，但引擎從不在 Ch7 之前顯示「碼片總數」，也沒有任何 NPC 提到碼片存在；玩家讀到 k-of-8 只會當成「沒通過的草案」。

**理由**：最少改動，沒有新發明，與聖經「先讀到，後來才懂」的設計一致。防劇透驗證器需將 `amend-10.draft` 列為白名單，否則合法內容會被擋下。

**與聖經關係**：聖經 Ch2 在 `/etc/charter.d/` 有 `amend-10.draft`（第十條，k-of-8）與 `amend-7.draft`；Ch3 在郵局揭露四位 Admin 身分；Ch6 用 git blame/log 才完整揭露 amend-10。兩種揭露層次（檔案可讀 vs 全文理解）已分開，本附錄僅確認遮蔽邊界。

## 6. 碼片順序的技術修正（接 D11）

真的 `ls -ltr` 排的是 mtime；硬連結共用同一個 inode，建立連結並不改 mtime。所以「順序藏在建立連結的時間」要改成：章節包用 `touch -d` 把八片的 mtime 設成不同時間。

**驗證用原生 Bash**：八片的 mtime 必須兩兩不同，不然 `ls -ltr` 會按檔名排。把兩片的 mtime 改成相同，驗證器必須抓到。

**與 D11 關係**：D11 已修訂規劃中的 `ls -ltr` 說法為「依碎片檔案最後修改時間排序」，不宣稱是每個硬連結名稱的建立時間。本附錄將該原則落實為章節包製作時的 `touch -d` 要求。
