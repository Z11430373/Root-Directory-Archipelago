# 版本路線圖與製作關卡

版本 0.2｜設計基線，全部未來里程碑仍需實際證據。

依據：[總綱](../《根目錄群島》完整版規劃書.md)、[D01–D04](../DECISIONS.md)、[狀態](../STATUS.md)。角色／相對成本是規劃分工，不是已量測工時或排程承諾。

## 1. 發布模型

- **M5＝主線 1.0**：桌機完整離線敘事、可靠保存、九分支、五結局、基本可操作性與有界離線交換。
- **C1＝後續內容包**：紅隊七案、夜班七夜與完整多人衝突關卡，可分批發布。
- **M6＝線上 1.1**：同步與授權重放。C1 未全部完成不阻擋 M6。
- **M7＝線上 1.2**：經濟、領地、賽季與 QDUOJ。先小型試營運，再十二週正式驗證。
- **2.x**：完整獨立接力與其他模式；Ch4 的 NPC 管線小關卡仍在核心章節。

## 2. 依賴圖（規劃）

```text
本輪規劃／來源盤點／有界可行性研究
       │
M0 真人試玩＋活動回饋 → M1 共用基礎 → M2 Ch0–Ch2 → M3 中段 → M4 內容 RC → M5 主線 1.0
                          │              │                                  ├→ C1 內容包（各案獨立）
                          │              └→ 小型 Ch5／Ch6 玩法研究           └→ M6 線上基礎 → M7 賽季
                          └→ 保存／重放格式研究（不等到 M6 才設計）
```

研究可先開始，受影響正式內容的製作／發布仍需解除各自缺口。正史未知不讓所有工程停擺，也不讓工程原型假冒正文。

## 4. 提早研究的高風險事項

| Spike | 要回答的問題 | 最小可觀察實驗 | 不成立時的處理 |
| --- | --- | --- | --- |
| S-01 保存 | 新版在不同瀏覽器能否重建任意修改與 hardlink？ | 一小型 VFS、兩分支、匯出再匯入、改錯一個關係 | 修保存契約，保持原 RA1 reader |
| S-02 判題 runtime | 真 Python 的下載、離線、取消與限制是否可接受？ | 固定小題、無網路、無限迴圈與記憶體壓力；列依賴與授權 | 程式 profile 不開放；主線繼續用指令／代辦 |
| S-03 百萬行 | 生成／排序／中斷能否在目標設備預算內？ | 指定 seed、實際裝置與資料量；記錄峰值記憶體及取消延遲 | 調整工作集與關卡資料規模，保留目標能力 |
| S-04 Boss | 玩家能否從可觀察狀態推導下一步？ | 三階段小遭遇、觀察免費、行動節拍、局部重試 | 改因果與訊號；不以縮短倒數增加刺激 |
| S-05 mini-git | 小型歷史能否形成有趣且正確的調查？ | 少量 commit、一個可重現 good/bad predicate、log/blame/bisect | 縮小指令支援與史料量，不虛構 git 語意 |
| S-06 後半劇情 | 提案有沒有足夠來源及角色因果？ | 來源矩陣、兩方案比較、作者正文核對 | 保留提案，不補造隱藏結局 |

研究執行仍屬後續工作；本輪只交實驗規格，不捏造數據。

## 5. 產能與成本記錄

每個工作包記錄：輸入是否齊備、代理輪次、作者審閱時間、實作時間、找碴／修正輪次、人工試玩時間、重工原因、外部依賴等待。代理輸出字數與文件數不是產能成果。

以完成的同類包估算下一包，為章節標記複雜度：資料／新命令／新互動／新時鐘／新判題／結局連動。沒有可比樣本時保留區間與不確定性，勿用 Ch0 工時直接乘九。

## 6. 可縮範圍與保護項

依序延後：2.x 獨立模式 → 賽季常態營運 → C1 批次規模 → 完整手機主線與裝飾。

不以縮範圍犧牲：已宣稱平台的基本操作、可讀性、保存／恢復、免費主線出口、分支隔離、正史來源與結局的完整性。

若必須砍 Ch3.5／結局，需同時修改總綱承諾、角色與伏筆、來源變更紀錄、可達性測試及對外版本名稱；不沿用「完整五結局 1.0」標籤。

## 7. 路線圖驗收

- ROAD-01：每個模式在總綱、此表及工作包只有一個發布歸屬。
- ROAD-02：M5 不依賴 C1；M6 不依賴 C1 完成；WP7 不依賴 mini-git。
- ROAD-03：M0 真人未完成時，狀態只可標研究／規劃，不標製作關卡已通過。
- ROAD-04：未知隱藏結局不得被排程表中的「五結局」字樣掩蓋。
- ROAD-05：每個退出條件可指出實際檔案／執行紀錄／人工紀錄，沒有日期即不作日期承諾。
