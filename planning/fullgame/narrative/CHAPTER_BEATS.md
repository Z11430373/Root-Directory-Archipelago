# 九章節拍、證據操作與回訪契約

版本：0.2-draft｜2026-11-02｜狀態：Ch0–Ch1 來源整理＋遷移規格；Ch2–Ch7 為有來源錨點的節拍提案。

## 目的與依賴

把每章的「為何現在要做」連到「玩家查了什麼，因而改變什麼」。供章節作者寫場景、引擎作者實現 gate、活動主持人決定入場摘要。

依賴：[決策](../DECISIONS.md)、[來源狀態與衝突](../SOURCE_MAP.md)、[角色弧線](STORY_ARC.md)、[揭露 gate](REVEALS_AND_ENDINGS.md)、[口吻](VOICE_AND_COPY.md)、[主筆實際回應](AUTHOR_RESPONSE.md)、[SAVE_SCHEMA_2 §5.2](../engineering/SAVE_SCHEMA_2.md#52-投影映射使用原白名單不補造事實)。所有後半場面與情緒因果標 P，不擴充成未取得的正史。本文的「故事處理／證據已讀／協助完成」是語意狀態，**不是新 schema 欄位名**；實際欄位由引擎與存檔規格統一定義。

## 1. 所有章共用的入場與離章規則

1. **主線進場**：檢查上一章已處理的故事狀態，而非所有可選遺物、所有知識卡、所有程式 AC。玩家需要的前情以已讀證據組成短摘要，不說「你曾經做過」未記錄的事。
2. **章內三條路**：親自操作、免費逐步協助、`skip`／代辦。協助需展示最小因果證據與可回看的摘要；純 skip 記「已跳過」及必要故事效果，不憑空記獨立解題、親自驗證或已取得分支卡。需要卡時可免費回訪證據操作。
3. **局部回報**：每個主要操作至少得到一種可感知差異——輸出縮小、檔案恢復、角色回答改變、狀態修復；不能只有右上角數字增加。原附件 2–3 分鐘回饋與章長是待真人校準的目標，不以牆鐘驅動劇情處罰。
4. **回訪**：世界主線狀態不倒退；已完成處給「重看／在副本重試／補未讀」入口。重新閱讀不重發獎勵。分支世界效果留在分支，知識合併依 D08。
5. **獨立活動**：以帶版本的活動快照提供當章所需情境；開場明示「活動預設前情，不代表你的主線經歷」。只展示本章必要前情；有後半揭露的活動需玩家選擇入場，不能在選章卡面先洩漏。活動完成不整包覆蓋主線；可匯入的知識證據及其揭露時機另驗。
6. **提前持有知識**：朋友／活動資料先記來源，未到本地揭露 gate 的標題、卡文、對話保持待開啟。不能因收件就讓 NPC 說玩家親眼見過。若玩家已在活動實際讀過後半內容，不假裝能抹掉記憶；只維持主線記錄的真實性。
7. **時間**：D07 的虛擬時間只由明示推進或規定關卡動作前進。閱讀、暫停、離線、放大文字不造成損失。活動倒數到點只保存／交班，不等於 GC 掃蕩。
8. **最後選擇前**：依 D14 建立可回訪存檔，提供尚可調查的島／已知文件入口；不能用「再也回不去」假壓迫遮蓋未明的必要條件。
9. **B0/B1 分支處置（B D19）**：主線可直接選「稍後調查」，只記 `flag.b0.deferred`／`flag.b1.deferred`；`branchHandled(Bx) = done OR deferred`。merge／abandon 才記原 done；新版 tag 收藏但不退出。延期、退出、親見證據、取得卡四件事分開；朋友卡也不自動產生自己的 done。

## 2. Ch0〈值班第一天〉｜lighthouse

**來源錨點 S**：`s0.1–s0.9`、Q0-1…Q0-5、F1、R0、T0100、B0→K0；lin 親手熄燈，貓隨燈復工。詳見 SRC-02/08/09/11。

- **進場動機**：回應低優先、無倒數的呼叫；眼前目標只是讓燈塔重新有人值班，不先給「拯救全世界」責任。
- **學習能力（3）**：①用 `ls`／`ls -a`、`cd` 建立位置與可見性概念；②用 `cat`、`grep`／`grep -r` 從檔案找證據；③在 B0 分清分支破壞與主線保存。
- **錯誤假設（P，供引導用，不聲稱所有玩家都這樣想）**：燈壞了，所以只要啟動；前任的叮嚀已經解釋一切；刪檔等於永久弄壞存檔。

**情緒因果與操作節拍**

1. 呼叫機說只有玩家回應，信卻早已留好。讀手冊讓陌生空間有一個可依靠的聲音。
2. 查 `lamp.log` 找到 `stopped by uid=lin` 與 02:00:00：操作修復忽然變成「他為何離開」的調查。輸出只證明停止者與時間，不幫玩家推斷動機。
3. 隱藏草稿交出 F1 與找兩個人的叮嚀。玩家得到的是託付的感覺，不是已知道碎片總數。
4. 點燈、貓復工、地圖亮起，立即回報「做一件小事確實有用」。B0 再讓玩家安全試錯；讀 `/lost+found/#0` 才有可帶回的 K0 證據。
5. **情緒收尾**：來源的「燈塔今晚有人值班」承認玩家的在場；日誌港的閃燈把好奇引向一個具體的人。P：不把 T0100 做成感謝的付費或程式能力門檻。

**入口／出口契約**

## 3. Ch1〈日誌港〉｜logport

**來源錨點 S**：`s1.1–s1.9`、Q1-1…Q1-5、T0427、F2、R1、B1→K1；Q1-3 建 `ckpt/ch1-night`。日誌目標量不是已完成效能證據。

- **進場動機**：港口有人值班但燈在閃；幫他從日誌中回答一個問題，而非要求把百萬行讀完。
- **學習能力（3）**：①精確欄位／錨定比對；②分段管線、統計與重導向，檢查中間輸出；③在本遊戲 `fsck` 模擬中區分檢查與修復，讀回復原檔。
- **錯誤假設 P**：最常見就最危險；相似 IP 都是同一個；封掉可疑訪客便能安心；會說故事的人一定知道全部。

**情緒因果與操作節拍**

1. harbor-master 誇口、喝茶，使讀日誌的壓力先轉成可笑的困境。404 的誤比對讓玩家知道「看似合理的數字」仍要查欄位。
2. 管線把資料縮成可讀證據；申訴日與鐘塔把憲章從告示變成出事後的補洞。查到 GC 的定時探測，規律反而引起不安。
3. 復原 lin 的信，港務員先想聽又縮回去。玩家救回的是寫給某個人的話，F2 因而不只是清單獎勵。B1 可先於信進入；未讀信版本不說「lin 已經叫你試」。
4. B1 的可觀察結果必須區分精準封鎖／誤傷車隊／封錯對象。親得 K1 或有效 peer K1 都能用來問 harbor，這次主線提問才產生停下茶杯的回報；不要求朋友知識重做模擬，不因摧毀主線獲得尊敬。
5. **情緒收尾**：來源「我沒有更動它」不是宣布 GC 永遠無害；是玩家帶著更多資訊、較少確信地離港。下一站三人門將控制欲轉成協作問題。

| 情境 | 規則 |
| --- | --- |
| 回訪 | B1 可重跑其他 outcome；K1 去重但保留 collateral 證據。可在取得 K1 後補問 harbor，先讀信／後讀信均不漏掉回應 |
| skip／協助 | T0427 由 `shell-local`／`assisted` 真正產出、驗證／交付報表可支撐離港；Python AC 只來自真程式判題。B1 可直接明選延期記 deferred 並離港，不必跑模擬；進分支後 merge／abandon 才記 done，延期與 abandon 都不給 K1。有效 peer K1 可提問但不自動改分支處置 |
| 獨立活動 | 給港口快照與「已有值班員抵達」前情；不宣稱玩家做過 Ch0。K1 結果若匯入早期主線，內文等當地 gate 到達才展示 |
| 試玩匯入 | 記得本人 GC 名字與投票，可由正式版本模板進入 `ckpt/ch1-night` 對應模擬，標 legacy-projection；缺歷史時不列可還原原 snapshot。Q1-1/Q1-3 正式統計重做。投票不能觸發 harbor.softens |

**驗收 NAR-202**：沒有 Python runtime、零鑰匙幣仍能離港；B1 三結果＋先分支後讀信可達；T0427 縮小範例的 GC 前三名不得說成真實日誌排名。

## 4. Ch2〈權限堡〉｜permfort

**來源錨點 S**：`ls -l`、`chmod`、`id`、`sudo`；三人簽核；lin 最後一任 Admin 揭露；F3 提示 `/etc/charter.d/.seal`；B2 改第三條的 v2.5→v3.4 OOM 模擬，K2〈憲章為防囤積而生〉；保留 v2.4 原口令、amend-7、amend-10。完整章檔未有。**下列串場均 P。**

- **進場動機 P**：港口已能值班，但下一道門只認三個人；玩家想知道前任為何把「找兩個人」寫得那麼鄭重。
- **學習能力（3）**：①用 `id`、`ls -l` 分清使用者、群組與權限；②只變更需要的權限並比較前後，理解 `sudo` 不是口令；③區分現行條文、舊版口令與簽核證據。
- **錯誤假設 P**：能修的人就應該獨自拿全部權限；念對舊條文就等於現行授權；lin 只是轉述別人的規則。

**情緒因果提案**：玩家在 Ch1 建立了「我能診斷」的信心，卻在門前被自己的身分擋下，因此對規則感到惱怒。找出舊口令讓探索有回報，但門的語言謎題與實際簽核分成兩步，避免偷渡「口令即權力」。ada／bo 各覆核一件不同事項；兩者的保留意見有可查證理由，玩家因而不是求人給面子。B2 提供「把第三條改掉就好了」的實驗，結果只支持該模擬模型的後果。此時 lin 的 Admin 身分重新照亮先前的信：玩家被照顧，也確實被保留資訊。

**局部回報／情緒收尾 P**：依序得到可讀權限差異、合法簽核回報、F3 的已知來源入口；最後不是三人歡呼，而是玩家帶著一個更私人問題去找信——為什麼他一直不說自己是誰。F3 實際取法、字串與對話待資料包。

| 情境 | 規則 |
| --- | --- |
| 回訪 | 舊原文與 Rev 5 可對照；補 B2、草案調查。可以略過已看教學的重播，不等於把舊同意沿用到另一個操作；授權期限、範圍與是否須再簽依 O-N06，不先定永久授權 |
| skip／協助 | NPC 可示範三個角色各查什麼；單純示範只記教學／協助，不能記當次同意。只有正式授權規則成立且各角色真的簽署，才記對應簽核；角色與授權規則仍待 O-N06，不暗稱三名真人連線。B2 結果、K2 授予條件須後續資料確認，不能 skip 自動授卡 |

## 5. Ch3〈郵局島〉｜mailisle

**來源錨點 S**：`grep -l/-A`、`find`、mbox；F4 在 lin 未寄信附件；Ch3 揭露拆成八片；B3→K3，兩者完整內容未知。**下列串場均 P。**

- **進場動機 P**：得知 lin 身分後，玩家需要讀他對不同人的話，確認其安排而不是聽一段替他辯白的旁白。
- **學習能力（3）**：①先找檔名／位置，再取相關上下文；②區分信件標頭、引用舊文、正文與附件；③對照路徑與引用關係，避免把兩個名稱誤當兩份不同內容。
- **錯誤假設 P**：搜尋到名字就是完整語境；未寄出的信能證明對方收到；有八份安排就等於八個人都同意。

**情緒因果提案**：帶著被隱瞞的不舒服進郵局，玩家最容易只抓一句證明 lin 有問題的話。關卡先讓單一關鍵字得到不完整片段，再讓 `-A`、標頭與附件關係補出語境；不是用假證據戲弄玩家，而是讓他親自發現漏看了什麼。拆分 root 的確認因此不只是收集數量揭露，而是「一個人安排了讓其他人也能持有的方式」這個可被質疑的工程事實。未寄附件提供 F4 的既有方向；收到與未收到的區別仍保留，不能順便宣告所有人完成交班。

**局部回報／情緒收尾 P**：雜訊縮成一封可讀的信、附件可定位、F4 有來源；玩家從想要單一答案轉成擔心安排是否真的持續生效，排程礦坑成為可理解的下一項調查。B3 的新真相／K3 卡文留白，不能用本段提案直接填卡。

| 情境 | 規則 |
| --- | --- |
| 回訪 | 可補上下文、附件與 B3；未讀信仍列具體可找範圍，不能靠未知結局獎勵催收集 |
| skip／協助 | 展示「找到片段→補上下文→確認附件」的最小摘要；故事可前進，標協助；未讀原文不記成玩家曾讀某封信 |
| 獨立活動 | 只預置必要權限與郵局任務；選擇入場時告知包含金鑰安排的中段揭露。已知 lin 身分可作活動前情，但不補主線 Ch2 完成 |
| 揭露 gate | 八片總數在本章來源所指揭露之後才允許顯示；若 C01 決定 Ch2 提前，本章必須改為驗證／擴充，不能再演首次驚訝 |

**驗收 NAR-204**：證據文本可區分寄出／草稿與引用正文；總數第一次展示符合裁定的 gate；K3 未定不被寫成任意結局充分條件。

## 6. Ch3.5〈排程礦坑〉｜cronmine

**來源錨點 S**：`crontab`、`at`、時間推理；B3b→K4；F5 在閏日排程註解；世界 GC 大掃除 cron 為 `0 0 29 2 *`。原規劃稱 merge/fork 需要此章，完整條件未有。**串場 P；可晚補為 B D14。**

- **進場動機 P**：郵局留下的安排涉及未來；玩家想確認「下次」到底指哪一次，而不是因地圖多一個未打勾項目而來。
- **學習能力（3）**：①讀週期排程與一次性排程；②對照鐘塔時區、日期、下一次執行；③用明示虛擬時間推進驗證假設，區分觀察和等待。
- **錯誤假設 P**：看到時間字串就一定會執行；每月都有同一日期；讓遊戲開著等真實午夜才算解題。

## 7. Ch4〈網路群礁〉｜routereef

**來源錨點 S**：`ping`、`traceroute`、`ssh`；NPC 對手與管線小關卡；F6 提示「唯一仍可連通的一跳」；B4→K5。D03 明定主線 NPC 小關卡，完整管線接力另屬 2.x。**場面 P。**

- **進場動機 P**：玩家需要把證據送到下一站；已有同伴也不保證訊息能到達，失聯成為可診斷而非被遺棄的理由。
- **學習能力（3）**：①分清目標無回應與路徑問題；②用 `ping`／`traceroute` 對照每一跳、再決定 `ssh` 目的地；③檢查一段管線輸出是否符合下一位接手者的輸入。
- **錯誤假設 P**：第一個不回應的節點就是敵人；對方說完成等於整條工作完成；網路關卡必須真的連外。

**情緒因果提案**：前幾章教玩家信任可查證的人，本章讓信任遇到實際傳遞失敗。NPC 回報與玩家看到的結果不一致時，先提供可觀察輸出，而非暗示背叛。ada 偏重範圍、bo 偏重可用輸出（角色提案）的差異，讓玩家從選邊站轉向重現交接點。小管線接通後立刻得到下一跳可用的輸出，證明合作不是一句「友情」。F6 所在線索指向那個仍可連通的地方，不把猜 IP 當社交測試。

**局部回報／情緒收尾 P**：逐段亮起的可達狀態、格式可用的交班結果、F6 來源；同伴從「幫我過門的人」變成「知道該怎麼告訴我哪裡還沒好的人」。即將去的沼澤仍有風險，但風險不再必須獨自承受。

## 8. Ch5〈記憶體沼澤〉｜heapswamp

**來源錨點 S**：`ps`、`top`、`kill`、`ln`；Boss「回收波」三階段；F7 由 GC 保管；B5→K6；K1 有揭露破綻效果。Boss 逐階段動作、F7 交付與後半台詞未知。**節拍分工 P，不命名／填造原 Boss 階段。**

- **進場動機 P**：群礁已能交班，接手的系統卻持續受回收壓力；玩家需要讓被留下的東西有可持續存在的理由。
- **學習能力（3）**：①用 `ps`／`top` 區分行程、資源與瞬時狀態；②先診斷目標再 `kill`，觀察處理後果；③辨認硬連結名稱、共同 inode／內容與仍存引用。
- **錯誤假設 P**：殺掉最顯眼行程就能停止 GC；刪掉一個名稱就刪掉所有內容；知道 K1 就能背一行指令打贏。

**情緒因果提案（依來源分流）**：親做 B1 且已將證據帶回者，可回想自己觀測的封鎖後果；持有效 peer K1 者引用「收到的報告」，有本次主線提問紀錄才回顧港務員答覆；B1 延期且無 K1 者從免費現場觀察開始；只有 demo 投票者僅可回顧那次有來源的選擇，不稱已驗證封鎖。三階段應分別承擔診斷、實際改動、覆核結果的學習工作；具體配置仍待正文與引擎，不自創 Boss 數值。每段先允許暫停讀狀態，再讓操作推進，讓緊張來自要選什麼而不是打得夠不夠快。K1 帶來可提早注意的線索，沒有 K1 也有免費現場觀察與補訪；必需的主線理解不能藏在可漏卡裡。`ln` 的回報必須讓玩家看到保留的引用，而非 NPC 稱讚愛與勇氣戰勝回收。

**局部回報／情緒收尾 P**：可觀察壓力解除、保留引用的證據與 F7 的合法取得途徑（待定）。成功後留一個安靜節拍讀狀態，讓玩家感到自己「終於分清楚」，不是恨錯敵人後被說教。demo 註解提過 Ch5 遺物句，但本稿不補其全文、編號或結局用途。

| 情境 | 規則 |
| --- | --- |
| 回訪 | 三階段可從相應診斷點練習；重試不抹除主線已知、不重發 F7；可補 K1 後看不同提示來源 |
| skip／協助 | 可逐階段診斷／代辦並展示結果，記 assisted；暫停免費。不能以打字速度或提示次數剝奪主線出口 |

## 9. Ch6〈備份冰原〉｜coldstorage

**來源錨點 S**：`tar`、`gzip`、`diff`、`git log/blame/bisect`；F8 為 `v4-final.tar.gz` 唯一差異檔提示；B6→K7；lin v4.7 第七條與 art10 CI 原因；`/var/archive/hugs.log` 已登記。**串場 P。**

- **進場動機 P**：沼澤讓玩家見識制度代價；去備份不是找壞人，而是確認這套制度為何成為現在的樣子。
- **學習能力（3）**：①解包／解壓與 `diff` 比較可重查資料；②以 `git log`／`blame` 區分提交、行作者及現行內容；③以明示判定標準做 `bisect`，找引入變化的版本而非找罪人。
- **錯誤假設 P**：最新備份一定等於當時全部世界；blame 的名字就是應受罰的人；知道草案被擋等於已知道原因。

**情緒因果提案**：前任留下的溫柔現在有一整段失敗制度作背景。玩家先處理很具體的備份差異，得到定位 F8 的局部進展，才有能力讀更長的版本史。第七條由 lin 修改、art10 三種 CI 失敗並置，讓「他想交棒」與「他繞過規則」可以同時成立；不能把所有阻礙寫成愚笨官僚。`hugs.log` 若閱讀，情感來自嚴肅制度也留下小小照顧，不增加未知人物的悲劇。Ch0 已見「CI 說不行」的玩家此處獲得驗證理由，而不是被要求假裝第一次聽說。

**局部回報／情緒收尾 P**：差異可重現、作者／版本可定位、F8 有來源；玩家終於不必靠猜 lin 的心情來判斷方案。離島前提出是否還要回訪礦坑或早期分支，將理解轉為自己選擇下一步的能力。

| --- | --- |
| 回訪 | 原備份唯讀，試驗在副本；可重看差異與失敗紀錄，不能重新改寫歷史使選擇看似無代價 |
| skip／協助 | 給差異與證據鏈摘要，分清工具代辦與玩家判斷；不宣稱玩家已精通 git 或完整讀過每版憲章 |

## 10. Ch7〈根目錄〉｜`/`

**來源錨點 S**：`ls -ltr`＋`cat` 組 `root.key`、七／八片門檻、八空格標記、B7→K8、遺物收束；K0 有窺門效果；INIT 是 TICKET-0001 報告人在此揭露。**選擇流程 B/P；謎題與結局正文 U。**

**局部回報／情緒收尾**：P：整理一條已確認證據可得到明確回報；選擇前承認玩家一路做出的實際行為（含求助），不用「全部精通」套話。U：四結局結果、八空格作用、遺物如何收束、隱藏結局正文均不得代寫；因此目前不能宣稱此章敘事可發布。
