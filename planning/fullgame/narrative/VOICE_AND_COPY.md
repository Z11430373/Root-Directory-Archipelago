# 口吻、術語與功能真值文案

版本：0.2-draft｜2026-11-02｜狀態：既有口吻規則＋文案提案；未寫入來源 YAML／介面。

## 目的與依賴

讓情緒來自角色怎麼說，讓操作狀態來自確實發生的事。故事可以保留祕密，不能讓玩家猜存檔是否成功、程式是否真的執行、消息送給誰。

依賴：[來源地圖](../SOURCE_MAP.md)、[D05–D09/D15/D16/D19/D20](../DECISIONS.md)、[章節契約](CHAPTER_BEATS.md)、[揭露與授權](REVEALS_AND_ENDINGS.md)、[主筆回應](AUTHOR_RESPONSE.md)。下文所有新短句均標 **P／提案**，不代表可讀正史原句；D19/D20 的行為是整合者已採的規劃基線，不是作者正史批准。

## 2. root 的三義與容易混淆的術語

| 詞 | 對玩家第一次說明的方式（P） | 編劇／教學約束 |
| --- | --- | --- |
| 根目錄 `/` | 「`/` 是目錄樹的起點。現在說的是位置。」 | 能進根目錄不代表取得最高操作權；Ch7 的門有故事條件，不外推到真 Linux 根目錄皆有此門 |
| root 權限／帳號 | 「root 是高權限身分；憲章另規定誰能同意使用它。」 | 帳號身分、有效憑證、法律簽核分別查；三人是現行授權條件，不是碎片數 |
| GC root（可達性起點） | 「GC root 是回收判定追蹤引用的起點；這裡不是管理員帳號。」 | 這是遊戲回收模型的語意，需模型實作支撐；歸檔受保護不表示真 OS 中所有 hard link 永不回收 |
| `root.key` | 「拼接的檔案名稱；能做什麼還要看門與授權規則。」 | 不能把檔案生成等於八位守鑰者同意；具體權限模型仍未知 |
| 金鑰碎片 F1–F8／鑰匙幣 | 前期只說當前已取得碎片；貨幣明寫「鑰匙幣」 | 幣不補碎片，提示免費不等於碎片免費送；早期不能顯 `/8` |
| 三人／七片／八片／k-of-8 | 分別寫「三人簽核」「開門所需碎片」「特定結局必要數量」「未通過的授權草案」 | k 不填 3 或 8；第十條不自動替代第三條 |
| 硬連結／引用／備份 | 說明名稱是否共用同一 inode／內容；備份是另一份可比較資料 | 刪掉一個名稱與資料完全消失不同；跨島不自動等於跨檔案系統 |
| mtime／ctime／建立時間 | `ls -ltr` 的 t 明寫最後修改時間 | 不把 mtime 或 ctime 說成藏片時間；同 inode 別名共用 mtime |
| 憲章 Rev／世界 v | 「Rev 是憲章版次；v 是世界／Admin 時代。」 | 不將 Rev 5、v5.0、lin v4.7 混成同一時間線；xiaolin 不擅自改叫 lin |
| `git blame` | 「這些行最後由誰改動。」 | 不說「犯人是誰」；Rev 5 已廢除以 blame 罰人的舊附則 |
| `fsck` | 「本遊戲的 `fsck` 先檢查；這個關卡的 `-y` 會按已定資料修復。」 | 不宣稱真實 `fsck` 普遍安全、只讀或一定能復原任何被刪資料 |
| 可回訪／分支／讀舊存檔 | 主線旅行、模擬副本、另起較早歷史分別命名 | Ch3.5 本輪選目前主線旅行；不能把三種機制都叫「回到昨天」 |

## 3. 誰說的、誰做的、誰記得

1. **功能真值**：存檔、送出、判題、時間推進、授權、匯入結果以引擎回報為準。NPC 可不知故事動機，不能以不可靠敘述掩飾工具失敗。
2. **人物主張**：`harbor-master 說`與`日誌記錄`可並列；查無紀錄仍不能判定說謊。不要替港務員吹牛自動蓋「已驗證」章。
3. **玩家記憶**：本人讀過、本人操作、收到朋友報告各自保留來源。demo 投票只有本人遷移且原票明確才可說「你當時說過」；互斥雙票或來源不明依 SAVE §5.2 標 conflicted／不確定，不擅選最新票、不播單一確定回憶；peer 同暱稱亦不能冒成本人。
4. **關係記憶**：朋友 K1 可讓玩家提出有效問題；harbor 因這次主線提問而回應，之後可以記得這次談話。不能說他與玩家曾共同經歷朋友的分支。
5. **資料記憶**：重複匯入同一證據不多得好感、不再收簽名；未合併分支證據不能直接成為 main 既知。
6. **能力評語**：可稱讚玩家找到矛盾、願意委託、交付報表；只有實際執行判題才說程式通過，仍不直接宣稱已掌握整門技能。

### 4.2 T0427：同一故事回報，四種真實來源

**P 採用的 gate 事件**：「港務員收到符合故事報表規格的結果」。報表需由所標路徑真正產生／驗證並交付；只讀範例不算。故事報表規格與原程式題是否完全等價交判題規格，不以相同題號直接假定等價。

| 完成來源 | P／專屬短句 | 可共用的離港部分 |
| --- | --- | --- |
| `shell-local` | `[系統] 工單故事已處理：本地 Shell 結果已驗證並交付。本次交付未執行 Python；既有判題紀錄保留。`；`harbor-master: 你把報表整理出來了。這次不用我從頭看。` | 既有 `init.ch1_done` 的港口值班、今晚訪客、權限堡方向；觸發改依故事事件 |
| `assisted` | `[系統] 工單故事已處理：由協助流程產出報表並交付。本次交付未執行 Python；既有判題紀錄保留。`；`harbor-master: 報表收到了。你把這件事交接完了。` | 同上；不說「你寫的程式」 |
| `program-local` | `[系統] 工單故事已處理。Python：本地測試通過。`；`harbor-master: 程式的報表收到了。茶還是熱的。` | 同上；本地通過不稱線上認證 |
| `program-online` | `[系統] 工單故事已處理。Python：線上判題 AC。`；`harbor-master: 判題收據和報表都到了。` | 同上；只有真的收到對應版本有效結果才顯示 |

額外狀態（均 P）：

- 未提交／錯解：`[系統] 報表尚未交付。可以繼續修正，或使用免費協助。` 錯解顯示實際診斷，不預造 test #。
- Python 未開放：`[系統] 此版本尚未開放 Python 執行。可使用 Shell 路徑或免費協助處理故事工單。` 不顯示 WA/TLE。
- 舊檔只有 `flag.t0427_done`：`[系統] 舊紀錄標示工單已完成；未記錄可確認的執行來源。` P：保留既有故事進度，程式成績標來源未詳；不能重建假收據。
- 匯入真的 program AC 但報表尚未在當前 main 交付：記有效程式成績，給交付入口；不憑空產生本地 NPC 已收報表的關係記憶。

**本次交付與判題歷史的反例（TICKET §2.2）**：WA→代辦時，故事已處理／本次 assisted，程式欄仍顯原 WA 與 profile；本人有效 AC→Shell 交付時，保留本人 AC 與有效範圍，不改寫為未判定；peer AC→本人交付時，朋友結果只列來源報告，本人程式欄沿用本人的既有 verdict（無則未執行）。shell／assisted 不清空 `programVerdict`，也不把朋友結果寫入本人 AC。

### 4.3 T0100：「選修」與「燈已登記」的明確修訂

**P 採用方案**：`systemctl start lamp` 的 INIT 登記已使本次值班有效；T0100 是修復供之後簽到使用的登記工具，保持選修、題號、輸入輸出題意與 `TICKET-0100｜值班簽到` 名稱。不是再做一次才承認玩家點過燈。

必須在後續內容工作包修訂原工單「沒有登記，就沒有值班；沒有值班，燈就不算亮」的絕對斷言；**不能宣稱原文本來就是這個意思**。新背景短句（P）：

> 本次值班已由 INIT 登記。登記工具還沒修好；修好後，下一位值班員也能使用它。

T0100 的故事修復事件與 program AC 分欄。原 `init.t0100_ac` ID 保留作相容來源；其中感謝／第一支程式的既有親密對話可在已完成故事修復後使用來源適配變體，不能連帶顯示未實際取得的 AC／`uptime +3h` 效果。原事件拆分、節點引用與舊旗標映射由判題／存檔工作包明列，不能直接讓所有 `assisted` 呼叫原 AC 效果集。

### 4.4 有界交班與 `wall`

**P 模式契約**：1.0 的自由文字便條在本機檔案與明示交換範圍內；不等於公開聊天。舊 `wall <任意文字>` 廣播不在 1.0 開放；若保留命令相容回應，必須說明限制。線上預定義交班為後續版本能力，不提前說已送達真人。

| 情境 | P／新短句 |
| --- | --- |
| 本機便條 | `[系統] 便條已寫入這份本機存檔。尚未分享。` |
| 匯出便條 | `[系統] 此匯出包含你的便條與暱稱。收到檔案的人可以閱讀。` |
| NPC 足跡 | `[系統] 來源：單人模式同伴 op-ada。` |
| 朋友足跡 | `[系統] 來源：你匯入的朋友紀錄；不是目前在線狀態。` |
| 未開放 `wall` | `[系統] 此版本未開放廣場自由廣播。可在本機便條留下交班內容。` |
| 未來預定義交班 | `[系統] 交班訊息已提交到〈指定範圍〉。` 僅提交成功可說；「對方已讀」需另外的已讀事件 |
