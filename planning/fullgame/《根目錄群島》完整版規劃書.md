## 1. 北極星與範圍

**這份文件是什麼**：把《根目錄群島》從「15 分鐘試玩版〈第一夜〉」長成具有完整情感收束的離線長篇主線，再逐步擴充多人內容與賽季的施工藍圖。主線約 4–6 小時是待量測目標；十二週是後續線上賽季長度，兩者分開承諾。

**劇情依據**：[故事聖經連結](https://claude.ai/artifact/EFjvSgDXw45rqiBuucmoBv)目前要求登入，本輪未取得正文。已知事實以本機 `SCRIPT.md`、`world/`、`branches/`、`cards/` 與本附件可核對部分建立 [來源對照](SOURCE_MAP.md)。已公開／已實作內容保留相容；尚未發布的設計可提出有紀錄的修訂。後半新橋段、八空格意義及隱藏結局全文保持「待確認」，不由代理補成正史。

**北極星（一句話）**：在瀏覽器裡玩一個真的會壞掉、而且可以「回到昨天再試一次」的伺服器；學會的不是背指令，而是看懂系統為什麼這樣壞。

**三個同時要成立的目標**

- **玩家**：新手能從 `ls` 一路學會查證、提出假設、驗證與修復；熟手可自由探索與比較分支。速度挑戰獨立於閱讀主線，提示與跳過不剝奪故事出口。
- **活動**：每章可提供章節包、前情摘要與活動起始檔。既有單檔離線程式與活動工具可作基礎；真人活動成果仍需實際記錄。
- **作品集**：每個里程碑留下實際可展示的證據——存檔遷移、確定性狀態重放、對照與突變案例、真人卡點及因此作出的修訂。來源一致性、規則可達性與競賽授權分開呈現。

**四條不變原則**

1. **穩定資料 ID 與明確遷移**：保留既有章節、任務、角色、卡片 ID；schema 2 提供 schema 1／RA1 reader。活動限時與完整版長篇規則不以「嚴格子集」掩蓋差異。
2. **主線離線可完成**：世界語意與題目內容盡量共用；線上權威、競技費用與協作權限是明列的模式政策，不假稱所有規則完全相同。
3. **章節可獨立交付與入場**：一章包包含資料、測資、驗收、必要能力複習與有來源標記的 starter。活動 starter 不冒充玩家親自完成前章的成就。
4. **可觀察結果才算驗收**：實際工具支援子集作 GNU/POSIX 對照；遊戲擴充使用自身規格。已選代表性突變必須被攔截，並記錄未涵蓋範圍；真人理解與節奏另驗。

**支援界線**：遊戲是有界模擬 Shell。重放服務可驗證指定規則下的歷程，不證明真人、原創解法或完全無作弊。1.0 目標為桌機完整主線；手機先以 Ch0 為明確驗收入口，完整手機主線經實測後再擴大承諾。Python 程式題在離線 runtime 驗收前明示未開放，不以字串判斷假裝執行程式。

**五根玩法支柱**（每個功能都要能回答「它在強化哪一根」，答不出來就砍）

1. **共用行為、兩種介面**：群島模式與 Bash 模式共用引擎。影響世界的按鈕對應可辨識指令／動作；顯示偏好、查閱與面板操作不需污染遊戲事件鏈。
2. **壞掉的是系統，不是玩家**：失敗永遠有可讀的原因（log、錯誤訊息），學的是診斷。
3. **分支即時間機器**：在分支裡比較後果，只有符合規則的知識證據能合併回主線。原稿歸於「聖經第 1 節」，本輪依可讀 B0／B1 及 D08 定規格，不宣稱已核對外部正文。
4. **持續有意義的回饋**：每 2–3 分鐘形成一次進展是待真人校準的設計假設。回饋可以是排除假設、讀懂證據或人物回應，不強制打斷閱讀。
5. **沒有死路**：免費三階提示、`skip`、回顧與局部重試。完整解法需主動展開；長文閱讀不視為自動洩題的理由；故事完成與能力掌握分開。

**同一章的三種體驗差異**（Ch2）：單機由玩家與具明確立場的 NPC 完成簽核；離線協作交換各自的證據與同意紀錄；線上組隊另處理身分、等待與斷線。缺人時可採 NPC 補位，不偽稱三名真人同時在線。簽核規則、後期多簽與角色立場見 [劇情設計](narrative/STORY_ARC.md)及 [互動規格](ux/INTERACTION_SPEC.md)。

**完整體驗循環**：發現異常 → 查證 → 提出假設 → 操作／分支驗證 → 看見後果 → 更新交班筆記。每章有局部收束；續玩顯示位置、上次結果、未解問題與下一個可行動方向。主線暫停、設定、閱讀與離線不造成進度懲罰。

**分支與回訪的明確承諾**：B0／B1 可直接選「稍後調查」再離章，不要求先進分支才能退出；延期、退出、取得證據與取得卡各自記錄。`tag` 收藏而不退出。Ch3.5 回訪是在目前主線旅行，B3b 是另一個隔離實驗；實驗線索可帶回，F5 要在主線合法取得。這些新版規劃及舊 gate 的遷移見 D19–D20。

## 3. 系統架構

**一句話**：一個「確定性引擎」同時跑在瀏覽器和伺服器上——瀏覽器用它玩，伺服器用它重放驗證。資料、規則、判題、存檔各自獨立。

**六層**

| 層 | 職責 | 試玩版現狀 | 完整版要做的事 |
| --- | --- | --- | --- |
| 資料層 | 章節、工單、對話、知識卡、檔案系統快照的 YAML | 已有（Ch0–Ch1） | 每章一個章節包；編譯成 JSON，帶版本與雜湊 |
| 引擎層 | VFS、Shell 子集、flow、對話與交易 | 已有分離的 JavaScript 模組、Worker 中斷與回歸紀錄 | 漸進 TypeScript 與明確狀態／效果契約，保留 legacy 相容路徑 |
| 存檔層 | 事件、分支、檢查點、來源與可信度 | RA1 保存 notable 事件；本機 journal 另保存完整操作 | schema 2＋legacy reader；明定 VFS、cwd、快照、歷史與版本；`.rasave.json` 優先 |
| 判題層 | 指令／狀態判定與程式 judge profile | 七個試玩快題及對照案例 | 本地 `shell-state`；Python runtime 可行性關卡；QDUOJ 為不同執行 profile |
| 前端 | 終端、任務、證據、地圖、保存 | 已模組化；群島／Bash 模式；建置輸出單檔 HTML | 延續兩模式；長篇閱讀、交班摘要、分支與匯入預覽、手機入口 |
| 後端（1.x） | 重放驗證、帳號、存檔同步、賽季、OJ 橋接 | 無 | 見下方「後端」 |

**確定性契約**：固定引擎、章節包、judge 與生成器版本後，由狀態及顯式輸入產生新狀態與效果；狀態含 PRNG 進度與整數虛擬時間。引擎不直接讀牆鐘／宿主亂數；宿主事件經明示 adapter 轉成輸入。驗收比較重算後的狀態摘要、關鍵輸出與事件結果，不只重新雜湊客戶端提交的紀錄。活動牆鐘、故事鐘、賽季鐘分開，詳見 [引擎契約](engineering/ENGINE_CONTRACT.md)。

**一致的提交點**：新版持久模式先算候選結果，保存交易成功後才發布新世界；失敗保留目前世界並提供救援，玩家明選才切僅此分頁模式。有時間成本的行動先處理排程再執行，Boss 的預告也須遵循同一順序（D17）。

**語言與工具**

- **引擎：TypeScript＋瀏覽器／Node 共用核心**。從既有模組漸進遷移；先建立等價證據，不因語言更換擴大功能範圍。
- **Python 參考模擬器保留**：與文字契約、GNU 對照及既有回歸共同提供證據。參考程式也可能有缺陷，分歧需記錄裁決，不以兩份同源實作相同就推稱正確。
- **建置**：esbuild切成「引擎＋章節包」。活動單檔版（file://能力待驗），正式版靜態站＋按章下載＋Service Worker快取。D22先鎖全部預定章manifest目錄，Ch0-only bytes可開始，補齊已鎖Ch1閉包後同run續章；新發布但未鎖的章另走明示遷移。不將只裝首章標成完整離線。

**存檔成長與來源**：檢查點、快照、完整輸入歷史與無損壓縮分別定義。若裁切歷史，必須說明剩餘可回溯起點與信任範圍，不能再宣稱任意時間皆可重放。RA1 原碼與八碼 ID 保留；新版以 `.rasave.json` 為主，使用完整 SHA-256 摘要。舊檔未記錄的任意檔案與 cwd 不捏造還原，匯入先預覽並保留原始資料。詳見 [SAVE_SCHEMA_2](engineering/SAVE_SCHEMA_2.md)。

**後端（1.x）的三個服務**

1. **重放驗證**：分開記錄檔案完整性、指定版本下可重放性、賽季授權與收據。競賽還需伺服器發題、期限及單次結算；離線合法歷程不能自動升格為真人或競賽認證。伺服器收件時間也不等於玩家真實思考時間。見 [REPLAY_SPEC](engineering/REPLAY_SPEC.md)。
2. **存檔同步與帳號**：同人同祖先可 fast-forward；分歧保留雙方，讓玩家選擇接續或比較，不默默覆寫。朋友交換另用 peer 流程。先列事件內含的暱稱、便條、輸入等資料，供玩家預覽分享範圍；email 是否需要由帳號方案再定。見 [MERGE_SPEC](engineering/MERGE_SPEC.md)。
3. **OJ 橋接**：穩定故事工單 ID 加明確執行 profile／版本，映射到 QDUOJ 題號與測資版本。`shell-local`、`assisted`、`program-local`、`program-online` 分開；有相同語言、測資與正規化契約才可宣稱等價。結果提供世界內回應及可診斷的技術資訊。見 [TICKET_JUDGE](engineering/TICKET_JUDGE.md)。

**這個順序的理由**：先驗證 Ch0–Ch2 的完整玩家旅程，包括指令、分支、工單銜接、簽核與情緒動機；把它稱為「前段切片」，不以三章宣稱已完成半季時數。同步用極小資料試驗 Ch5 遭遇與 Ch6 歷史調查，提早找尾段風險。Ch3–Ch4 擴充資料與合作；Ch5–Ch7 完成因果與情感收束。

**章節包驗收模板**（每章都照抄試玩版的做法）

- 資料驗證器 0 errors；劇透護欄（不提前揭露碼片總數、結局）。
- 真工具對照：新增支援子集在固定工具版本與 locale 下對照；遊戲擴充另有可觀察規格。
- 至少三條走法：黃金、全程 `skip`、分支試誤；另驗任意檢查點離開／續玩、跨章回訪、舊檔匯入。跳過後有因果回顧，不冒充能力或程式 AC。
- 突變測試：指定資料、規則、判題與結局條件的代表性錯誤必須被抓到，記錄存活突變與範圍，不宣稱抓到所有未知錯誤。
- 時間預算：目標 25–40 分鐘一章（快／中位／慢三種玩家），整條主線約 4–6 小時；第一次真人試玩後重新校正。
- 匯入匯出：跨章與新版可攜狀態 round-trip；RA1 保留可恢復的 Ch0 進度、F1/K0 等白名單；Ch1 縮小版快題不直接當正式版已完成，INIT 可記得既有投票。具體依遷移規格，非單純更改 schema 號。
- 真人理解：說明本章一個因果、完成一個相近新情境；完成率、提示使用、跳過與理解分開計數。計畫與表單見 [PLAYTEST_PLAN](ux/PLAYTEST_PLAN.md)。

**指令白名單的成長**：試玩版以既有 29 個命令範圍為基線；完整版 70–90 個只是粗估，不作學習 KPI。每章以兩三項可遷移能力選擇命令。每個命令／選項具語意來源、支援範圍、替代解驗收與不支援回應；詳見 [COMMAND_COMPATIBILITY](engineering/COMMAND_COMPATIBILITY.md)。

## 5. 島嶼占領與經濟層

原規劃參數保留為待驗候選：每島 8×8＝64 區塊、完整度 0–100、快題占領／修補、慢題 OJ Boss、賽季時區 02:00 GC、每隊每週八小時維護窗、十二週與季末 `vote`。它們不是已證實公平的數值；設計詳見 [SEASON_SIM_SPEC](gameplay/SEASON_SIM_SPEC.md)，M7 前先做短期真人試營運。

**哪些在哪個層級**

- **單機離線**：不做領地。只有劇情與 NPC 世界的「地圖亮起來」效果，避免「單人假裝有對手」的承諾落空。
- **多人離線**：簡化版。每張存檔帶一份「戰報」，主持人用工具合併成全場地圖（適合社團、教室）；可信度標記為「自行回報」。
- **線上**：伺服器是唯一的真相。所有區塊變更都在伺服器端產生、重放、記帳。

**伺服器權威的戰鬥流程**

1. 玩家領取授權工單：伺服器綁定帳號、賽季、目標、題目／profile 版本、種子、單次 nonce 與期限。不同參數降低直接重用結果的價值，不排除分享通用解法。
2. 玩家在瀏覽器解題；快題送出「指令序列＋結果」由伺服器重放判定，慢題送出程式碼給 OJ 判題。
3. 依 D18，一份授權只受理一份 proof；語意失敗後重試需新 grant，系統重試沿用原 job。同 turn／起始版本的有效工作聚合後整批一次 CAS，原子更新區塊、帳本與逐單收據；重送不重複發獎。日報由已確認事件產生。
4. GC 每日 02:00（以賽季設定的時區為準）跑一個確定性的衰退任務；同一份事件日誌重跑，結果必須相同。

**經濟（鑰匙幣，暫定）**——全部是遊戲內貨幣，不接真錢，也不賣優勢。

| 來源（進） | 去路（出） |
| --- | --- |
| 合規工單結算與賽季獎勵 | 區塊修補、符合政策的維護預約 |
| 領地稅收（與維護成本共同模擬） | 僅適用競技模式的回溯資源；故事模式不收費 |
| 明列來源的活動／新人補助 | 登入歡迎詞等外觀；功能性備份策略另列能力與成本 |

修補等級屬能力／解鎖，不當成貨幣收入。主線 `man` 與三級提示免費；鑰匙幣為零仍可完成主線。舊付費提示設定的模式調整保留於決策／辯論紀錄。

**平衡的四條原則**

1. 將新人第一週存活作驗收目標；種子區塊與七天免維護只是候選政策，另測晚入賽季、隊伍大小與第八天落差。
2. 領地越大衰退越快，門檻是「保持活躍」，不是「一開始就拿到」。
3. 任何讓某隊長期領先、越領先越容易再領先的路，都要有至少一個機制把它拉回（維護成本、回收波、叛變季）。
4. 機制改動先在模擬器上跑。

**平衡模擬器（未開發）**：固定種子與代理策略模擬十二週，輸出資源分布、存活、維護負擔、領先持續性與晚入隊伍機會。壞參數案例需對應預先定義的指標門檻，不能只因參數變大就宣告失衡。加入低活躍、考試週與同解法分享情境。模擬驗證規則；真人試營運驗證是否願意回來。

**反作弊與濫用**

- 前端結果須經授權檢查、重放／判題與結算；種子＋nonce 不作真人或原創性證明。
- 每帳號每日上限只約束該帳號，不宣稱能單獨防多帳號；團隊／區塊／伺服器總量政策需另模擬。
- 解法分享與自動化無法由參數化單獨排除；先定義合作與競技允許範圍，再選擇相符的排名規則。
- 暱稱格式限制與檢舉機制；不收真名。

**採取的預設**：不做真錢、不做抽卡、不做開放聊天室；賽季結束時全部重置，只留「名人堂」與徽章。

## 6. 白帽模式與安全邊界

紅隊七案與夜班七夜保留為 C1 的內容範圍；原故事聖經章節正文待取得。可先規劃學習主題與案例模板，候選案不得冒充正史案號。詳見 [EXPANSION_MODES](gameplay/EXPANSION_MODES.md)。

**基本立場**：白帽模式教的是「理解攻擊面以便防守與修補」，每一案以「報告＋修補」為終點，不是以「拿到 shell」為終點。紅隊第一手、藍隊第一手都有，每案必交報告。

**硬邊界（不可讓步）**

1. **全部是自建的模擬靶機**：不連、不掃、不測玩家自己的真實網路與主機；模擬器不提供任何真實網路的出口。
2. **沿用模擬案例範圍**：以設定與邏輯錯誤的觀察、修補、回歸為重點；不提供對真實資產的利用流程。案例的具體教學與原稿限制一併接受真人審閱。
3. **不針對真實組織與真實網站**：劇情裡所有資產都是虛構。
4. **每案確認授權範圍**：突出本案資產、允許動作與較前案的差異，保留報告義務；確認可回查，不以長表重複簽名替代理解。
5. **白帽模式採模擬結果**：此模式判定指令／狀態與報告證據；不因此假稱其他程式工單已具離線執行器。兩者能力與判題 profile 分開。

**審核機制**

- 每案附一張「安全檢查表」：是否出現可直接複製的真實攻擊指令、是否指向真實系統、是否這一案的教學重點是「修」。
- 驗證器依案例 allowlist 與固定誤植測資檢查真實主機／公開 IP 等內容；語意、授權範圍與教學正確性仍需內容審閱，不把字串掃描視為完整安全證明。
- 外部審閱路線：白帽章節發布前，由不同於作者的人（你的老師或社群有資安背景的人）讀一遍，這一步無法由 AI 或自動工具取代。

**年齡與玩家範圍**：預設面向高中以上、有興趣的初學者；白帽模式標明「僅限模擬靶機」，每案結尾都要問「你怎麼修」。

**與主線的關係**：白帽／夜班是**可選**的，不影響主線結局；但完成後會解鎖「紅／藍的視角」跨章彩蛋。

**體驗與驗收**：紅藍可共用一個事件，從證據、影響、修補到驗證逐步形成報告；夜班側重優先順序與交班。每個已發布案例須章節包驗收、原訂內容檢查與真人審閱；主線 1.0 不依賴 C1 審閱完成。

**測試策略（有牙的測試）**：每個里程碑都要同時有以下四項。

- **對照測資**：真 bash／Python 參考模擬器的答案，前端和後端都要符合。
- **突變測試**：每個重要不變量配一個能違反它的代表案例；記錄 oracle、預期拒絕點與存活原因，避免只檢查實作自己的輸出。
- **真人試玩紀錄**：時間、卡關點、最常用的提示。這些才是「時間預算」的真正來源。
- **回歸測試**：固定 legacy 規則與測資版本；新規則使用新向量與遷移測試，不要求不同內容版本憑空得到相同鏈尾。完整追蹤見 [驗收矩陣](delivery/ACCEPTANCE_MATRIX.md)。

**成本（量級估計，不是報價）**

- **代理額度**：最耗的是「章節包的資料、驗證器、對照測資」。建議每章一個語境，不要一個語境做多章。

**可砍清單（越前面越先砍）**

3. 夜班 7 夜→先發布 3 夜；原稿建議夜 1、2、7，待正文與依賴核對後才選定。
4. 白帽 7 案→先發布 3 案；原稿建議案 1、3、7，不能把目前的候選練習當作這些正式案號。
5. 完整手機主線與次要視覺效果可延後；已承諾平台的基本閱讀、鍵盤、焦點、狀態宣讀與復原不列為可砍項。
6. Ch3.5 與五結局屬核心範圍。若真的縮減，必須改版本承諾、敘事依賴與驗收；不以刪支線默默消失兩個結局。

**核心不可犧牲**：可靠保存與誠實匯入、無死路、可理解的分支回復、基本可操作性、支援子集語意對照、重要不變量測試、原訂模擬邊界與劇情收束。

**作品集敘事**（給特殊選才與求職的「故事線」，不是宣傳語）
